# 06 · 专家并行 EP 与 5D 并行总览

> 对应原文：Expert Parallelism / 5D Parallelism in a Nutshell / Scope and focus / Summarizing it all

## 1. 专家并行 EP

MoE 的基本想法：每层不再只有**一个** FFN，而是若干**并行的**专家模块，token 被路由到不同专家去处理。

因为**各专家的 FFN 完全独立**，把每个专家放到不同 worker 上就行了 —— 这就是 EP。

**EP 比 TP 轻得多**：不需要切矩阵乘，**只需要把 token 的 hidden state 路由到正确的专家**。核心通信操作是 **all-to-all**（把 token 送到分配的专家、再把结果收回来）。

**EP 必须和 DP 一起用。** 因为 EP 只作用于 MoE 层、**不切输入 token**（不像 CP 沿序列切）。只用 EP 的话，所有非 MoE 的模块都在做**冗余计算**。EP+DP 才能同时把专家和输入 batch 都摊开。

> 📝 正因为 EP 在输入处理上与 DP 同构，有些实现干脆把 EP 视为 **DP 的一个子集**，唯一区别是 EP 走专家路由而不是每卡跑相同副本。

**工程技巧**：DeepSeek-V3 在 router 上加约束——**每个 token 最多发到 M 个节点（他们取 4）**，把 token 尽量留在单节点内以压低通信。V3 一共 **256 个专家**。

## 2. PP vs ZeRO-3：最容易混淆的一对

两者都是**沿模型深度轴**切权重并做通信（ZeRO-3 预取下一层、PP 传激活），**都是整层粒度**（与 TP/EP 的子层粒度不同）。区别：

| | **ZeRO-3** | **Pipeline Parallelism** |
|---|---|---|
| 每个计算单元存的是 | 一层的**一部分** | **完整一层** |
| 通信传的是 | **权重** | **激活** |
| 编排 | 模型无关 | 模型无关 |
| 实现难点 | 模型切分与通信复杂 | **高效的 PP 调度**复杂 |
| 扩展偏好 | 偏好**大 mbs / 大 seq_len** 来藏通信 | 偏好**大 grad_acc** 来摊薄 bubble |

> 一句话：**它们解决同一个问题，区别只在你选择把通信花在"传权重"还是"传激活"上。**

**能不能组合？可以，但实践中不常做**——要把全局 batch size 加得很大才能摊掉通信成本，在 gbs / 模型大小 / 带宽 / 效率之间形成拉扯。真要组合，应配置 ZeRO-3 **在一串 PP micro-batch 期间把权重留在显存里**，别反复通信。

**ZeRO-1 / ZeRO-2 与 PP 则很好配**（它们只管优化器状态和梯度，互补、无新问题）。**DeepSeek-V3 就是 PP + ZeRO-1。**

## 3. 各维度怎么组合

- **TP(+SP)** 与 PP、ZeRO-3 天然互补（靠矩阵乘的分配律），可以叠。
- **为什么不能只用 TP**：①通信在计算的**关键路径**上，过了某个点通信就压倒计算；②TP **不是模型无关的**——激活时而沿 h 分片、时而沿 s 分片，需要模型特定知识才能切对。而 ZeRO 和 PP 都不依赖特定模型
- **结论性的组合原则**：
  > **TP 留给节点内高速互联；跨节点的并行组交给 ZeRO-3（通信易重叠）或 PP（通信需求低）。**
  组织 GPU 分组时首要考虑：**TP 组必须落在同一节点内。**
- **CP** 和 **EP** 也帮着切激活，与 TP 互补，可以无障碍组合。CP 管超长序列（128k+，即使 full 重算也放不下时），EP 管 MoE。

---

## 4. 作用域：各技术影响模型的哪一部分

- **TP(+SP)**：影响**整个模型**（同时切权重和激活）。
- **CP**：主要影响 **attention 层**（唯一需要跨序列通信的地方），其它层各自独立处理分片序列。
- **EP**：只影响 **MoE 层**（替代普通 MLP），attention 等不变。
- **PP / ZeRO**：**不特定于任何子模块**，例外是 PP 需要各段**层数均衡**——首尾 stage 因为多了 embedding 层通常要特殊处理。

| | TP + SP | CP | EP |
|---|---|---|---|
| 切什么 | 沿 hidden/seq 切权重与激活 | 沿 seq 切激活 | 切专家权重与激活 |
| 通信为了 | 矩阵乘（column/row linear） | attention 的 K/V | token 路由到专家 |
| 模型无关性 | **需要模型特定实现** | 除 attention 外模型无关 | 除 MoE 层外模型无关 |
| 偏好 | 节点内高带宽 | 长序列 | 需要 MoE 架构 |

## 5. 一张总表

| 方法 | 省的是哪块显存 | 沿什么维度切 | 缺点 |
|---|---|---|---|
| **DP** | 激活（靠减小本地 batch） | batch | 受最大 batch size 限制 |
| **PP** | 模型参数 | 模型层 | **空转 bubble + 调度复杂** |
| **TP+SP** | 模型参数**和**激活 | hidden 维 / 序列长度 | **要求高带宽通信** |
| **CP** | 激活 | 序列长度 | attention 里增加通信 |
| **EP** | 专家参数 | 专家维 | 需要 MoE 层 + 路由通信 |
| **ZeRO-1** | 优化器状态 | DP 副本间分片 | 参数通信开销 |
| **ZeRO-2** | 优化器状态 + 梯度 | DP 副本间分片 | 参数通信开销 |
| **ZeRO-3** | 优化器状态 + 梯度 + 参数 | DP 副本间分片 | 参数通信开销 |

**没有银弹，实际总是要组合。**

## 6. 与本项目的关系

- nano 走到 V8.2 已经有 **DP × TP × PP × CP** 四根轴（EP 因为 Qwen3-0.6B 是 dense 且 gloo 无 all-to-all 而记录设计不实现，见 v8.md 偏离表）。本章那张组合原则表说明 nano 的取舍是标准的：**TP 组同 NUMA/同节点**正是 V8.2 G5 拓扑检查在做的事。
- 「PP vs ZeRO-3」那张对比表值得单独记住：nano 同时实现了 **FSDP（=ZeRO-3，V7）** 和 **Megatron PP（V8.2）** 两条后端，正好是这张表的左右两列。V9 若要解释「为什么 FSDP 和 Megatron 的吞吐特性不同」，答案就在**「传权重 vs 传激活」**这一行。
- 「PP 偏好大 grad_acc、ZeRO-3 偏好大 mbs/seq」这条**直接可用于 V9 的扫参数设计**——两个后端的最优扫描方向本来就不同，不该用同一组参数去比。
