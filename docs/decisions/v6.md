# V6 实施计划：主线三启动 —— 真 log_probs + 真 GRPO + 真 torch 训练一步（GSM8K）

> 状态：✅ 代码 + 离线 + 5090 端到端全链路跑通（**主线三第一版**）。
> 源锚点：`agentic/ToolOrchestra/{orchestra_solver.py,custom_convert.py}` + `slime/backends/fsdp_utils/actor.py` + `slime/utils/ppo_utils.py`。

## 目标

A3 收官后 nano 是"结构忠实但训练是假的"教学骨架（假 token / 无真 log_probs / fake trainer /
fake weight_sync / 单样本 reward）。V6 把这四根假支柱换真，在 GSM8K 上跑通一条**真 RL 训练闭环**：
真 token+log_probs（SGLang /generate）→ 真 GRPO 组归一（同题多 rollout）→ 真 torch 训练一步
（PPO policy gradient）→ 真权重同步回 SGLang。用户目标是**纯复现真训练机制全链路**，不追求刷准确率。

数据集选 GSM8K：答案 `#### 数字` 可严格验证、小模型裸答多步算术会错、天然需 calculator 工具。

## 范围

- **做**：GSM8K 数据源（本地 parquet，服务器连不上 HF）+ calculator 确定性工具；SGLang 原生
  /generate 真 token+log_probs；移植源 custom_convert 的 GRPO 组归一；单卡 torch 真训练一步；
  真权重同步（disk reload）；train/eval + before/after 答对率。
- **不做（记录设计）**：FSDP/Megatron 多维并行（TP/PP/CP/EP，留 V7/V8）、CPU offload、dynamic
  packing、KL 惩罚项、critic/PPO-GAE、多 SGLang 专家集群、FAISS、tensor 广播权重同步。

## 内部四刀

- **V6.0**：GSM8K 数据源 + calculator 工具（复用 V1 CalculatorTool），离线验 calculator 真求值+回灌。
- **V6.1**：orchestrator 走 SGLang /generate 拿真 token_ids + 真 log_probs（对齐源
  `_generate_with_tools`）；真 tokenizer(apply_chat_template) 补齐"手工渲染"偏离；Sample 加
  rollout_log_probs 字段。
- **V6.2**：移植源 custom_convert（组内 min-max + GRPO 标准化 `(r-mean)/(std+eps)` clip[-3,3] +
  std<0.1 过滤 + 按 turn 拆样本），opt-in via `custom_convert_path`。补 A3 登记的最大偏离。
- **V6.3**：torch 真训练一步（loss 对齐源 ppo_utils.compute_policy_loss）+ 真权重同步（disk reload）。

## 验证结果

- **离线全绿**：`scripts/test_v6_gsm8k.py --offline`——calculator 真求值+回灌、仅 orchestrator token
  可训练、GRPO 组归一数值有区分度（错误=0、fast 优于 precise、标准化组内均值≈0 clip[-3,3]、
  无方差组被 mask）、GRPO 接入 train_ray 闭环。V0/V2/V3/V4/V5/A1/A2/A3 回归全绿。
- **5090 端到端全链路 PASSED**（0.6B@30000，rollout/训练模型一致）：
  - `real_logprobs OK (tokens=240, nonzero_lp=15)`——**V6.1 真 log_probs 工作**（/generate 返回真
    token+非 0 log_prob，`len(tokens)==len(loss_mask)==len(rollout_log_probs)`）。
  - 真 torch 训练：rollout 0 `train=11.2s`（真 backward，含首次编译），weight_version 每轮递增
    2→3→4（**真权重同步发生**，`sync≈18-19s`=save_pretrained 落盘 + SGLang /update_weights_from_disk
    热重载的真实耗时）。
  - 组内方差**确实出现**：某轮 `reward_mean=-0.346`（同题 4 rollout 有对有错→GRPO 归一出负
    reward→该轮 `train=1.7s` 真算了梯度），另两轮 `reward_mean=0.000`（组内无方差→全 mask）。
    印证 GRPO 语义：**有对错差异才有学习信号**，采样随机性是方差来源。
  - `acc_before=0.400 acc_after=0.200`——acc **变化了但未提升**（甚至轻微下降）。这恰恰证明
    **权重真被改变**（否则 acc 恒定）——机制全链路真实发生。未稳定提升的原因：训练量微不足道
    （4 题 × 3 轮 × 单步 lr=1e-6）、GSM8K 对 0.6B 过难、多数轮组内无方差被 mask。V6 目标
    （复现真训练机制全链路）已达成；**稳定提升 acc 是训练规模/超参调优问题，非机制问题**，留后续版本
    （调采样温度制造方差、换难度适中题、加大 n 和训练轮数）。

## 偏离登记（按铁律三要素）

| 偏离点 | ①源怎么做 | ②为何偏离 | ③等价性/何时补齐 |
|---|---|---|---|
| **单卡纯 torch，无 FSDP 多维并行** | 源 `fsdp_utils/actor.py` 用 FSDP mesh + TP/PP/CP/EP + CPU offload + dynamic packing | nano 单卡训 0.6B，多维并行是分布式吞吐工程，会淹没"真训练一步"这个概念 | **loss 数学等价**（同一 PPO policy loss 公式）；并行/offload/packing 留 V7 FSDP、V8 Megatron |
| **关 KL loss + entropy（use_kl_loss=False, entropy_coef=0）** | 源 loss = pg_loss + kl_coef·kl - entropy_coef·entropy，含 ref 模型算 KL | nano 取最纯 GRPO policy gradient，语义是源在这两系数为 0 时的特例；不起 ref 模型 | 主项（pg_loss）完全等价；KL 正则 + ref 模型留后续 |
| **权重同步走 disk reload（save_pretrained→/update_weights_from_disk）** | 源用 tensor/distributed **bucket 广播**（免落盘、进程内换权重、更快） | nano 不接管 SGLang 进程内存、单机最简可用；disk reload 语义清晰 | **换权重语义等价**（训练后引擎用新权重）；实测 sync≈18s 是落盘+reload 真耗时；tensor 广播留 V7 |
| **逐样本前向，不做 packing** | 源把多样本 pack 成一条长序列做一次前向（吞吐优化） | nano batch 小，逐样本清晰优先 | loss 数学等价（都只在 loss_mask=1 处 sample-mean）；packing 是吞吐优化留 V7 |
| **GSM8K 替代源 STEM/HLE + calculator 替代 search+FAISS** | 源 QA 是 STEM/HLE 网络知识题，search 调 FAISS 检索服务 | nano 要"调工具才答对+答案可严格验证+base 有提升空间"，且不起检索服务 | **结构等价**（calculator 同为"非终止工具、结果回灌"）；数据集换可验证数学题是 RL 实验需要 |
| **只两工具（calculator/answer），砍 enhance_reasoning** | 源 QA 三工具 enhance_reasoning/search/answer + 多专家 | nano 只需 calculator + answer 说清"确定性工具 + 专家路由 + 多组件 reward" | 路由分发语义等价；更多工具可加 |
| **GSM8K 本地 parquet 加载** | 源 datasets/JSONL 加载 | 服务器 HF/github 不可达（CLAUDE.md 已记）；parquet scp 到服务器本地目录 | 结构等价（同 question/answer 字段）；有网时回退 datasets.load_dataset |
| **acc 变化但未稳定提升（0.4→0.2）** | 源大规模训练、足够多组有对有错、多轮迭代 → 稳定收敛 | 0.6B、4 题×3 轮×单步 lr 训练量微不足道；多数轮组内无方差被 mask | **机制正确且权重真被改变**（acc 变化即证据）；稳定提升是训练规模/超参问题非机制问题，留后续（调温度制造方差/换适中难度/加大 n 和轮数）|
