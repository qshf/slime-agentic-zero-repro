# V9 方案（最终版）—— 离线精度 + 在线性能全对比

> 状态：**确认中**（2026-08-18）
> 一句话：先用**离线固定 batch** 验证精度等价（Megatron vs 单卡 torch），再用**在线 agentic RL 闭环**对比端到端性能——前八版都在问「对不对」，V9 第一次问「采用 Megatron 后快多少」。
>
> **V9 的核心对比**：历史版本（V6/V7）用**手写单卡 torch 训练**（`TorchActor`），V9 引入 **Megatron TP×PP×CP 并行**（`MegatronTrainer`），在相同 rollout 引擎（SGLang）和相同编排逻辑（V5 Ray 主循环）下，直接测量两者的精度等价性和端到端性能差异。

---

## 0. 核心思路：分层验证

### 为什么要分"离线"和"在线"

**离线（train 模块隔离测试）**：
- 排除 rollout 的随机性（agent 生成的 tokens 每次不同）
- 用固定 batch 验证 Megatron 与单卡 torch 的**数学等价性**（loss/梯度）
- 测量各模块纯净时间（forward / backward / optimizer / 通信）

**在线（完整 agentic RL 闭环）**：
- 真实场景：rollout（agent 推理）→ train（梯度更新）→ update_weights（权重同步）
- 端到端对比：有 infra（SGLang + Megatron）vs 无 infra（HF + TorchActor）
- 回答"加了这套 infra，实际场景下快多少"

2. **`toy_rl/utils/flops_utils.py`** —— 简化版（只支持 dense Qwen3）
   ```python
   def calculate_fwd_flops(seqlens: list[int], config) -> int:
       """逐条样本算前向 FLOPs = Σ层(qkv + attention + output + mlp) + lm_head
       
       公式对齐源 slime/utils/flops_utils.py:66-127，但只支持 dense（无 MoE/LoRA）。
       
       每层 FLOPs：
         - qkv 投影：2 * seqlen * hidden * (num_heads*kv_channels + 2*num_kv_groups*kv_channels)
         - attention：2 * num_heads * seqlen² * kv_channels / 2 (QK^T causal) 
                    + num_heads * seqlen² * kv_channels (A*V)
         - output：2 * seqlen * hidden * hidden
         - mlp(SwiGLU)：2 * seqlen * hidden * ffn_hidden * 3 (gate/up/down)
       
       lm_head：2 * seqlen * hidden * vocab_size
       
       注意：
         - 逐条算（不是 max_len × B）—— 真实 FLOPs 不含 padding 的浪费
         - GQA：num_query_groups ≠ num_attention_heads
         - vocab_size=151936 在 0.6B 上是大头
       """
       total_flops = 0
       for seqlen in seqlens:
           # 每层
           layer_flops = (
               _qkv_projection(seqlen, config) +
               _attention(seqlen, config) +
               _output(seqlen, config) +
               _mlp(seqlen, config)
           )
           total_flops += layer_flops * config.num_layers
           # lm_head
           total_flops += 2 * seqlen * config.hidden_size * config.vocab_size
       return total_flops
   ```

3. **在关键路径加埋点**

   修改 `toy_rl/trainer/megatron_trainer.py` 的 `train_batch`：
   ```python
   from toy_rl.utils.timer import Timer
   from toy_rl.utils.flops_utils import calculate_fwd_flops
   
   def train_batch(self, samples, ...):
       timer = Timer()
       
       # 1. 构造 batch
       timer.start("batch_preparation")
       batches = [self._build_batch(...) for ...]
       timer.end("batch_preparation")
       
       # 2. forward + backward（Megatron schedule 包了两者）
       timer.start("forward_backward")
       torch.cuda.synchronize()  # ← 必须 sync，否则测的是 launch 时间
       losses = forward_backward_func(...)
       torch.cuda.synchronize()
       timer.end("forward_backward")
       
       # 3. optimizer
       # 注：_finalize_model_grads（三处 all-reduce）由 config.finalize_model_grads_func
       #     在 forward_backward_func 内部反向结束后自动触发，外层无调用点可包 timer。
       #     通信开销折叠在 forward_backward 时间里；V9.3 在 _finalize_model_grads 内部细分。
       timer.start("optimizer")
       torch.cuda.synchronize()
       grad_norm = clip_grad_norm_(...)
       self.optimizer.step()
       torch.cuda.synchronize()
       timer.end("optimizer")
       
       # 5. 计算 FLOPs（从 batches 提取 seqlens）
       seqlens = self._extract_seqlens(batches)
       fwd_flops = calculate_fwd_flops(seqlens, self.config)
       
       return {
           "loss": ...,
           "timer": timer.log_dict(),
           "fwd_flops": fwd_flops,
           "tflops": 3 * fwd_flops / timer.log_dict()["forward_backward"] / 1e12,
       }
   ```

### V9.1 · 离线精度门（隔离 train 模块）

**目的**：验证 Megatron 与单卡 torch 的**数学等价性**，排除 rollout 随机性干扰。

**新增脚本**：`scripts/bench/v9_accuracy_gate.py`

```python
"""V9.1: 离线精度门 —— 固定 batch 验证 Megatron vs 单卡 torch 等价。

对比项：
  1. loss 值
  2. 梯度（全局 rel_L2 + cosine）
  
门标准（对齐 V8.2）：
  - bf16：rel_L2 < 5e-2, cosine > 0.999
  - fp32：rel_L2 < 1e-5, cosine > 0.99999
  
注意：
  - Megatron 用 TP=1（单卡，无通信干扰）
  - 两者从同一份 HF 权重载入
  - 对比前需要映射参数名（Megatron vs HF）
"""

def load_fixed_samples():
    """固定 5 条样本（从 V8.2 测试复用或手写）。"""
    return [
        {"tokens": [...], "loss_mask": [...], "reward": 1.0},
        # ... 共 5 条，每条 ~500 tokens
    ]

def run_accuracy_gate(dtype=torch.bfloat16):
    samples = load_fixed_samples()
    
    # 1. Megatron（TP=1, PP=1, CP=1）
    megatron = MegatronTrainer(model_path, tensor_model_parallel_size=1, 
                               params_dtype=dtype, backend="gloo")
    megatron.optimizer.zero_grad()
    loss_m, _ = megatron._microbatch_backward(samples, len(samples))
    grads_m = {n: p.grad.clone() for n, p in megatron.model.named_parameters() if p.grad is not None}
    
    # 2. 单卡 torch（复用现有 TorchActor）
    from mini_slime.torch_actor import TorchActor
    args_torch = Args(train_backend="torch", train_model_path=model_path, ...)
    torch_actor = TorchActor(args_torch)
    torch_actor.model = torch_actor.model.to(dtype)
    torch_actor.optimizer.zero_grad()
    loss_t = torch_actor.train_batch_internal(samples)["loss"]
    grads_t = {n: p.grad.clone() for n, p in torch_actor.model.named_parameters() if p.grad is not None}
    
    # 3. 对比
    print(f"Loss: Megatron={loss_m:.6f}, Torch={loss_t:.6f}, Δ={abs(loss_m-loss_t):.2e}")
    
    # 梯度需要映射参数名
    name_map = build_megatron_to_hf_name_map()
    metrics = compare_grads(grads_m, grads_t, name_map)
    print(f"Grad: rel_L2={metrics['rel_L2']:.2e}, cosine={metrics['cosine']:.6f}")
    
    # 门判定
    threshold = {"bfloat16": 5e-2, "float32": 1e-5}[str(dtype).split(".")[-1]]
    assert metrics["rel_L2"] < threshold
    assert metrics["cosine"] > 0.999
    print("✓ 离线精度门通过")
```

### V9.2 · 在线端到端对比（完整 agentic RL 闭环）

**目的**：在相同 rollout（SGLang）和相同编排（V5 Ray 主循环）下，直接量化**历史手写单卡 torch 训练（V6/V7 路径）vs 引入 Megatron 并行后的训练**的端到端性能差异。

**两条路径**：

| 路径 | rollout | trainer | 权重同步 | 并行 | 对应版本 |
|------|---------|---------|---------|------|---------|
| **历史路径**（手写 torch） | SGLang 服务 | `TorchActor`（单卡） | disk reload | 单卡 | V6.3/V7 |
| **V9 路径**（Megatron） | SGLang 服务 | `MegatronTrainer`（TP=2） | disk reload | TP×PP×CP | V8.2 |

**关键**：两条路径的 rollout 引擎、权重同步、编排逻辑完全相同，**只对比 train 阶段**的手写单卡 torch vs Megatron 多卡并行——这正是 V9 的核心问题。

#### 编排：复用 V5 的同步/异步双主循环（算法部分不新写）

V9 **不新写编排逻辑**，直接复用 V5 已对齐源项目的两个主循环：

| nano 文件 | 源项目对应 | 角色 |
|---|---|---|
| `mini_slime/train_ray.py` | `train.py:65-93` | 同步基线：`ray.get(generate(N))` → `ray.get(train(N))` |
| `mini_slime/train_async.py` | `train_async.py:31/39/62` | 异步：预取 `generate(N+1)` overlap `train(N)` |

两者的**唯一本质差异**就是源注释那句 *"one can change the position of the sync operation(ray.get)"* ——
V9 只是把 `args.train_backend` 从 `fake` 换成 `torch` / `megatron`，编排代码一行不改。

**这正是 V9 兑现 V5 欠账的地方**（v5.md 已登记）：
V5 的 `async 193.7s < sync 209.3s` 是靠 `fake_train_seconds=5.0` **sleep 模拟**出来的时间窗。
V9 的 train 是**真的**（torch 单卡 / Megatron TP=2），所以：

- `args.fake_train_seconds = 0`、`args.fake_gen_seconds = 0`（两个旋钮全关，真时间说话）
- overlap 能藏住多少，取决于**真 train 时间 vs 真 gen 时间**的比例
- `update_weights_interval` 会**周期性打断 overlap**（源 `train_async.py:62-66`：换权重前必须
  `ray.get` 掉在途 generation，那一刻并行断掉）—— 这是 V5 只在注释里写、从未实测的那条

因此在线对比是 **2 × 2 矩阵**（trainer × 编排），而不是两条线：

| | 同步（train_ray.py） | 异步（train_async.py） |
|---|---|---|
| **无 infra**（TorchActor 单卡） | A | B |
| **有 infra**（Megatron TP=2） | C | D |

四格都跑，能同时回答两个问题：
- **横向比**（A vs B、C vs D）：异步 overlap 在**真 trainer** 下省了多少（V5 欠账）
- **纵向比**（A vs C、B vs D）：Megatron 并行在 train 阶段快了多少（V9 主问题）

若只跑两格，就分不清"快"是来自并行还是来自 overlap。

#### 额外要记的两个量（源已有对应口径）

- **`wait_gen_time`**（`train_async.py:58-61` 已在记）：异步下若 ≈ 0，是 overlap 生效的铁证
  （V5 实测 rollout 1/2 的 `wait_gen=0.000s`）。对应源 `train_metric_utils.py:38-42` 的
  `wait_time_ratio = train_wait_time / (train_wait_time + train_time)`。
- **`policy_version_gap`**（`learner_metrics.py:87` 已有）：异步导致的 off-policy staleness。
  V5 登记过「nano fake reward 感知不到，留真 agent 时显现」—— V9 是真 trainer + 真 SGLang，
  第一次能把 gap 和 reward 放在一起看。**V9 只记录不优化**（修 staleness 是后续版本的事）。

**新增脚本**：`scripts/bench/v9_end_to_end.py`

```python
"""V9.2: 在线端到端对比 —— 真实 agentic RL 闭环（rollout → train → update_weights）。

实验设置：
  - Agent：A2 AgentFlow（主线二已收官）
  - Prompts：5 条 GSM8K math 问题
  - 轮数：2 轮（观察权重更新后的变化）
  - 重复：3 次取中位数
  
对比项：
  1. 单轮 wall-clock（rollout + train + sync）
  2. 各相位时间（rollout / train / sync 分别占比）
  3. 吞吐率（tokens/s, tflops）
"""

def run_无_infra_path(prompts: list[str], num_rounds: int):
    """无 infra：SGLang + TorchActor（单卡）。"""
    # 启动 SGLang 服务（若未启动）
    # 用现有的 mini_slime/train_ray.py，设 args.train_backend="torch"
    args = Args(
        train_backend="torch",  # 单卡 TorchActor
        train_model_path=model_path,
        num_rollout=num_rounds,
        custom_generate_path="agentic.agentflow.rollout.generate",
        custom_reward_path="agentic.agentflow.rewarder.reward_func",
        use_sglang=True,  # 用 SGLang rollout
        sglang_url="http://localhost:30000",
    )
    
    # 加 Timer 埋点
    from mini_slime.train_ray import train
    timer = Timer()
    asyncio.run(train(args))
    
    return timer.log_dict()

def run_cell(backend: str, mode: str, num_rounds: int) -> list[dict]:
    """跑 2×2 矩阵的一格。**编排代码复用 V5，不新写**。

    backend: "torch"（无 infra，单卡）| "megatron"（有 infra，TP=2）
    mode:    "sync"（train_ray.py ≡ 源 train.py）| "async"（train_async.py ≡ 源 train_async.py）
    """
    args = Args(
        train_backend=backend,           # 唯一要换的旋钮
        train_model_path=MODEL_PATH,
        num_rollout=num_rounds,
        # 两条路径共用 SGLang rollout（V6 既有）
        use_sglang=True,
        sglang_url="http://localhost:30000",
        custom_generate_path="agentic.agentflow.rollout.generate",
        custom_reward_path="agentic.agentflow.rewarder.reward_func",
        # **V5 的两个模拟旋钮全关** —— V9 用真时间（这是 V9 兑现 V5 欠账的关键）
        fake_train_seconds=0.0,
        fake_gen_seconds=0.0,
        update_weights_interval=1,       # 先固定 1，Q4 的延伸再扫 {1,2,4}
    )
    if backend == "megatron":
        args.tensor_model_parallel_size = 2

    # 编排整体复用 V5：只在这里选同步还是异步
    if mode == "sync":
        from mini_slime.train_ray import train      # ≡ 源 train.py
    else:
        from mini_slime.train_async import train    # ≡ 源 train_async.py

    return train(args)   # 返回 metrics_log（每轮一个 dict，已含 wait_gen/train_time/weight_version）


def main():
    # 2×2 矩阵：trainer × 编排。四格都跑，才能分清「快」来自并行还是 overlap。
    CELLS = [
        ("torch",    "sync",  "A 无infra+同步"),
        ("torch",    "async", "B 无infra+异步"),
        ("megatron", "sync",  "C 有infra+同步"),
        ("megatron", "async", "D 有infra+异步"),
    ]
    NUM_ROUNDS, REPEATS = 3, 3   # 每格重复 3 次取中位数（共享 GPU 噪声大）

    results = {}
    for backend, mode, label in CELLS:
        print(f"\n=== {label} ===")
        runs = []
        for r in range(REPEATS):
            metrics_log = run_cell(backend, mode, NUM_ROUNDS)
            # 丢 warmup：第 0 轮含 CUDA context / NCCL 建链 / cuDNN autotune
            steady = metrics_log[1:]
            runs.append({
                "wait_gen": np.median([m["wait_gen_time"] for m in steady]),
                "train":    np.median([m["train_time"] for m in steady]),
                "total":    sum(m["wait_gen_time"] + m["train_time"] for m in metrics_log),
                "reward_mean": np.mean([m["reward_mean"] for m in steady]),
                # 异步的 off-policy staleness（V5 登记过、从未实测）
                "policy_version_gap": np.median([m.get("policy_version_gap", 0) for m in steady]),
            })
            print(f"  repeat {r+1}: total={runs[-1]['total']:.2f}s "
                  f"wait_gen={runs[-1]['wait_gen']:.3f}s train={runs[-1]['train']:.3f}s")
        results[label] = {k: np.median([run[k] for run in runs]) for k in runs[0]}

    df = pd.DataFrame(results).T
    # 横向比 = overlap 收益（A vs B、C vs D）；纵向比 = 并行收益（A vs C、B vs D）
    df["wait_time_ratio"] = df["wait_gen"] / (df["wait_gen"] + df["train"])
    print("\n" + df.to_string())
    df.to_csv("docs/decisions/v9_end_to_end.csv")
    plot_2x2(df, "docs/decisions/v9_end_to_end.png")
```

**要预先写下的预期**（§4 纪律 4：先测后编解释是自欺）：

- **B < A**（无 infra 下异步省时间）：gen 是大头（V6 实测 gen=30-70s vs train=1.7-11s），
  overlap 应能藏掉几乎整个 train。
- **D vs C 的收益比 B vs A 小**：Megatron 的 train 更快 → 能藏的东西更少，overlap 边际收益递减。
- **C vs A 的 speedup 远低于 2×**：0.6B 模型每层计算量小、TP 每层两次 all-reduce 激活、
  本机无 NVLink（0-1 / 2-3 同 NUMA，跨组 SYS）→ 通信占比高。
- **`wait_gen ≈ 0` 只在异步格出现**，且 `update_weights_interval=1` 会每轮打断一次 overlap
  （源 `train_async.py:64` 换权重前 `ray.get` 掉在途 gen）。
- **`policy_version_gap` 在异步格 = 1，同步格 = 0**；若异步格的 `reward_mean` 明显低于同步格，
  就是 staleness 第一次在真实数字上显形。

### V9.3 · 通信开销细粒度分析（暂缓实施）

## 3. 关键点

### 为什么要"离线 + 在线"两步

- **离线（V9.1）**：排除 rollout 随机性，**只测 train 模块**的数学等价性
- **在线（V9.2）**：真实场景，**测完整流程**的端到端性能

### SGLang 在哪里

**两条路径都用 SGLang 做 rollout**（V6 已有）：
- 启动 SGLang 服务（30000 端口）
- rollout 通过 `/generate` API 拿 tokens + log_probs
- train 后通过 `/update_weights` 同步权重（disk reload）

**区别只在 trainer**：
- **无 infra**：`TorchActor`（单卡，V6.3/V7）
- **有 infra**：`MegatronTrainer`（TP=2，V8.2）

这样更公平：rollout 引擎相同，权重同步相同，**只对比 train 阶段的单卡 vs 分布式**。

### 参数名映射问题

Megatron 的参数名 vs HF 的参数名不同，V9.1 对比梯度时需要映射：
