## V7.0 FSDP2 单样本真训一步（2026-07-29）

建 `toy_rl/utils/fsdp_utils.py`（wrap/mesh/init-context/broadcast）+ `toy_rl/trainer/fsdp_trainer.py`
（FSDPTrainer.init + train_step）+ `scripts/test_v7.0_fsdp_single.py`（torchrun 2 卡）。

**教学核心 = 同一份 loss 数学，换到分片后端上跑**。loss 公式与 V6 `mini_slime/torch_actor.py`
**完全相同**（同一 GRPO policy gradient）；差别只在执行后端——V6 单卡整模型 + padding batch，
V7 FSDP2 逐层分片 + 单样本前向。对照能看清「后端替换不改 loss 语义」。

**忠实 tie 处理（本版最关键的对齐）**：Qwen3-0.6B `tie_word_embeddings=True`（服务器实测确认）。
- `apply_fsdp2` 里 embedding 只在 `not tie` 时才 `fully_shard`（对齐 actor.py:956）——tie 时
  input/output embedding 共享权重，单独 wrap 会破坏 tie，故**不 wrap**。
- init 建模型时按 tie 选设备上下文（`get_init_weight_context`）：tie=True → **全 rank load 全量到 CPU**
  （对齐 actor.py:217-226 的 `use_meta_tensor = not tie`）；否则 rank0 CPU + 其余 meta device 省内存。
  tie 模型走 meta device 会在 broadcast 时 hang，源专门规避，nano 忠实照搬。

**loss 缩放**：`loss * dp_size / global_batch_size`（对齐 actor.py:677）。V7.0 单样本 gbs=1。

验证：`torchrun --nproc_per_node=2 scripts/test_v7.0_fsdp_single.py` **2 卡 PASSED**——
`q_proj.weight` local shard=1048576=全量 2097152 的一半（**2-way 真分片**）；loss=-2.0
（on-policy ratio=1、adv=1 → masked_mean=1 → -1×dp_size(2)/gbs(1)=-2.0，数学精确）；
grad_norm=308、权重 L2 变化 0.14（真梯度真更新）；tie 模型未 hang。

**踩坑（已修，见 commit 9e383cc）**：①`accelerate` 缺失——`init_empty_weights` 依赖它，
补进 pyproject `[train]` extra 并装（源也用 accelerate）；②`_no_split_modules` 在 transformers 5.x
是 `set` 不是 `list`，测试用 `[0]` 索引报错——改成成员测试（membership 对 set 本就 OK，只是断言写法错）。

## V7.2 梯度累积（2026-07-29；多样本微批补充 2026-08-06）

在 FSDPTrainer 加 `_microbatch_backward`（多样本微批 forward+loss+backward，累积不 step）+ `train_batch`
（zero_grad 一次 → 逐微批累积 → 末尾 clip+step 一次）；`_micro_backward` 保留为单样本兼容入口，
`train_step` 保留为 gbs=1 单微批的薄封装。新增 `scripts/test_v7.2_grad_accum.py`。

**教学核心 = 累积多微批的梯度 == 一次大批的梯度**。每微批 loss 乘 `dp_size/global_batch_size`：
FSDP 反向自动按 dp_size 平均梯度，两者相抵 → 累积所有微批的梯度，等于对全局批取
「逐样本 mean 之和 / gbs」的单次梯度。这就是梯度累积「不增显存等效放大 batch」的原理。
对齐源 `_train_core`（zero_grad 一次 + 遍历微批）+ `_train_step` 的 step 门控（`(mbs_id+1) in grad_accum`）。

**多样本微批（2026-08-06 补充）**：源项目将多条样本先 packing 成一个 microbatch，再以该 microbatch
做一次前向、反向；只在梯度累积边界执行 `optimizer.step()`。nano 尚未有 flash-attn varlen packing，
所以 `FSDPTrainer.train_batch(..., microbatch_size=N)` 先按本微批最长序列 padding，逐样本计算 masked mean，
再把该微批的逐样本 loss 求和后按 `dp_size / global_batch_size` 缩放。这样能如实呈现「多样本/微批」
与「跨微批累积」两个语义层次；padding 只增加无效 token 计算，非源的吞吐最优路径。V7.1 补齐 packing
后应以 packed varlen forward 取代此过渡实现。

验证：`torchrun --nproc_per_node=2 scripts/test_v7.2_grad_accum.py` **2 卡 PASSED**——
**累积等价性 max_diff=0.000e+00**（两条独立累积路径梯度逐参数精确相等，确定性前向下比容差更强）；
train_batch 处理 2 微批、grad_norm=166、权重 L2 变化 0.14（真累积真更新）。
`loss=0.0` 是**预期正确**：两样本 adv=+1/-1、on-policy 缩放后 loss=-1/+1 求和相消；但梯度对不同
token 不相消（grad_norm≠0）——正演示「loss 抵消 ≠ 梯度抵消」。V7.0 回归 PASSED（train_step 重构后不变）。

## V7.1 sequence packing —— 暂缓（决策记录）

**决定不实现 packing，改直接做 V7.2/V7.3**，原因是硬件缺失使「忠实对齐」不可得：

- 源 `pack_sequences` 把多样本 flat 成 1D、per-sample **reset position_ids**、`attention_mask=None`，
  **靠 flash-attn varlen 内核**（读 position_id 归零边界）实现样本间注意力隔离（对齐 `data_packing.py`
  + `actor.py` 用 `attn_implementation="flash_attention_2"`）。
- 服务器实测**无 flash-attn**，RTX 5090（Blackwell sm_120）编译 flash-attn 极其困难。
- 缺 flash-attn 时，packed 序列 `attention_mask=None` 会让样本 B **注意到**样本 A——
  **隔离静默失效、loss 悄悄算错**，这比不做更危险。

**忠实的 nano 替代**（能装 flash-attn 时补齐）：用 `cu_seqlens` 物化一个**块对角 attention mask**
显式隔离（打包概念不变，只是把 varlen 内核隐式隔离改成显式 mask——反而更易教）。留待 V7.3 后或
服务器装上 flash-attn 时补。**登记为偏离**（见下表），不假装做了。

## V7.3 Ray + FSDP + 权重同步（2026-08-06，代码完成待服务器验证）

把 V7.0/V7.2 的 `FSDPTrainer`（原来只在 `torchrun` 单脚本里跑）**搬进 Ray actor**，在 Ray 编排下
形成真 `torch.distributed` 进程组，闭合 `rollout → train → update_weights`，权重走 disk reload
同步回 SGLang。这是 V7 收官刀，兑现偏离表 #4「权重同步待 V7.3」。

**教学核心 = 同一份 FSDP 训练，从 torchrun 直起换到 Ray actor 编排下多进程协同**。loss 数学、分片、
累积全不变（V7.0/V7.2 已证）；本版只解决「Ray actor 之间怎么形成 dist 进程组 + 权重怎么同步回引擎」。

**关键对齐（源 `slime/ray/train_actor.py:29-71` + `actor_group.py:94-106`）**：
- **actor `__init__` 里设分布式 env**（`MASTER_ADDR/PORT/WORLD_SIZE/RANK/LOCAL_RANK`），
  `dist.init_process_group` 留到 `init()` 阶段（nano 里即 FSDPTrainer.__init__，在 actor.init 内构造）——
  等所有 actor 建好、env 就绪，各 rank 才集体 rendezvous。
- **rank0 先起、暴露自由端口，RayTrainGroup 广播给 rank>0**（对齐源 actor_group.py:95-106 的循环）。
- **`async_init` 并发发起 `init.remote` 再统一 `ray.get`**：不可循环里逐个 ray.get——fsdp 的 init 含
  集体 init_process_group，串行等第一个会死锁（R4）。
- 类装饰器 `@ray.remote(num_gpus=0)` 改**运行时包装** `ray.remote(num_gpus=N)(cls)`（对齐源
  actor_group.py:90）：fake/torch 选 0、fsdp 选 1（每 rank 一张卡）。

**两个必须对的正确性点（老 v7-plan.md 完全没提，这版才补）**：
1. **LOCAL_RANK 恒设 0，不是 rank**（对齐源 `get_local_gpu_id`，train_actor.py:20-25）。Ray 给每个
   actor 独占 `CUDA_VISIBLE_DEVICES`，actor 视角里可见设备恒索引 0。若用 rank，rank1 会去 `cuda:1`
   （它只看得到一张卡）→ invalid device。这是最易踩的静默 bug。
2. **权重同步 = 集体 save + 仅 rank0 POST**（对齐源 actor.py:744-746 的 barrier + if rank==0）。
   `FSDPTrainer.save_pretrained` 是集体操作（各 rank gather 分片到 rank0），故 `RayTrainGroup.update_weights`
   fan-out 让**每个 rank 都进** save；但落盘 + SGLang POST + 权威 version 只 rank0 一次
   （`WeightUpdater` 加 `rank` 门控），否则重复 reload / version 分叉。

**DP-split（双卡）**：Trainer 里列 dict → 逐样本 list → 按 rank 跨步分片 `samples[rank::world_size]`
（对齐源 `_split_train_data_by_dp`，rollout.py:818）；`train_batch` 的 `dp_size/global_batch_size`
缩放（V7.2 已实现）让累积梯度 == 全局批 mean。**约束**：world_size 须整除全局样本数，否则某 rank
分不到样本、跳过 FSDP 反向的集体 reduce → 与其他 rank 死锁（测试配 n_samples_per_prompt=4，world 1/2/4 均整除）。

**落地文件**（均对齐源、最小增量）：`args.py`（+`train_backend="fsdp"`/`fsdp_world_size`）、
`ray/actor_group.py`（master env + rank0 端口广播 + 运行时包装，~40 行）、`ray/placement_group.py`
（fsdp 时 `ray.init(num_gpus=world_size)`）、`trainer.py`（fsdp 分支 + 列→list 适配器 + DP-split，~30 行）、
`weight_sync.py`（rank 门控，~10 行）、`scripts/test_v7.3_fsdp_ray.py`（new，镜像 test_v6 服务器段）。
**复用 `train_ray.train` 不建 `train_fsdp.py`**（同步主循环 backend 无关，V6 torch 后端就这么复用）——
纠老 v7-plan.md 的 trap（它说的 `TorchTrainer` 类不存在，是 `Trainer` 分支）。**不改** `fsdp_trainer.py`
/`fsdp_utils.py`/`rollout_manager.py`/`torch_actor.py`。

**验证**：离线全回归**绿**（V0/V2/V3/V4/V5/V6/A1/A2/A3——改 actor_group/Trainer/WeightUpdater 签名后

## V7.5 sequence packing —— 退休偏离 #1（2026-08-08，代码完成待服务器验证）

兑现 V7.1 暂缓时预登记的忠实替代：给 `FSDPTrainer` 加一条 **opt-in** packing 前向路径，
用**显式块对角 4D mask** 替代源的 flash-attn varlen 隔离，证明它与 padding 路径 **loss/grad 逐值等价**，
从而诚实退休偏离 #1（详见 [v7.5.md](v7.5.md)）。

**教学核心 = 同一份 GRPO loss 数学，只换"怎么算 cur_lp"**：padding 是每样本一行 `[B,L]` + 按行 2D mask；
packing 是所有样本 flat 成 `[1,T]` + position_ids 每段 reset + **块对角 mask 隔离段间注意力**。loss（ratio/clip/
masked-mean/dp_size 缩放）走**同一** `_grpo_sample_loss`（本版把它从 `_microbatch_backward` 抽出共用）。

**关键对齐 + 偏离（源 `data_packing.pack_sequences` + `actor.py:801` `_get_model_inputs_args`）**：
- 源 forward：`input_ids=[1,T]`、`position_ids=[1,T]`（每段 reset）、**`attention_mask=None`**——靠
  **flash-attn varlen 内核**读 cu_seqlens 边界隐式隔离（跨段不计算，O(T) 块级稀疏）。
- 5090 是 Blackwell sm_120，**既无 flash-attn 也无 TransformerEngine**（infra spike 用 TE）→ 照搬
  `attention_mask=None` 会让整个 pack 走满因果注意力、**样本间静默串扰、loss 算错**。
- nano 改传**显式物化的 `[1,1,T,T]` 块对角因果 mask**（infra 文档承认这是源 varlen 路径的 "conceptual
  equivalent"，只是 varlen 内核不物化它）。隔离语义等价、吞吐**部分**等价（消除 padding 浪费，但付 O(T²)
  mask+compute、不得 varlen 块级稀疏）。

**两个必须对的正确性点**：
1. **transformers 5.x 接受自定义 4D mask 作 bias、不重推因果**（本版 #1 风险，已核源）：
   `masking_utils.create_causal_mask` → `_preprocess_mask_arguments` 对 `len(shape)==4` 的 mask
   **early-exit 原样返回**（不 re-expand 2D 因果）；`eager_attention_forward` 把它当**加性 bias**。
   约定：加性 float，`0.0`=attend / `torch.finfo(dtype).min`=blocked（**不用 `-inf`**——全屏蔽行 softmax
   会 NaN；`finfo.min` 安全）；dtype 须匹配激活（= FSDP MixedPrecision `param_dtype`）；`position_ids` 必传（RoPE 读）。
2. **仅 eager/sdpa 后端 honor 4D mask**（flash/flex 会**无视** → 静默串扰、loss 错）→ `_packed_backward`
   **硬断言** `model.config._attn_implementation in ("eager","sdpa")`。宁可炸也不静默算错。

**跨边界 target 不泄漏**（双重隔离：mask + shift）：per-segment `[start:end)` 取 `logits[start:end-1]`
预测 `tokens[start+1:end]`，边界 token 对下一段首 token 的预测**从不形成**——与 padding 路径的 `[1:]` 右移、
源 `unpack_sequences`+`sum_of_sample_mean` 逐值一致。

**落地文件**（opt-in、零回归）：`toy_rl/trainer/data_packing.py`（new：`pack_sequences` + `build_block_diagonal_causal_mask`）、
`fsdp_trainer.py`（抽 `_grpo_sample_loss` 共用 + `_packed_backward` + `train_packing` flag + `compute_dtype`）、
`fsdp_utils.py`（`apply_fsdp2` 加 `param_dtype` 参数，fp32 副证用）、`args.py`（+`train_packing`）、
`trainer.py`（透传 flag）、`scripts/test_v7.5_packing.py`（new）。默认 `train_packing=False` → V7.0/V7.2/V7.3 padding 路径不动。

**验证**：离线全回归**绿**（opt-in 默认 off，fake/torch/padding 路径不破）。**服务器 5090（world=1）**验等价：
`torchrun --nproc_per_node=1 scripts/test_v7.5_packing.py`（bf16 主门 `TOL=0.08`，对齐 infra spike bf16 bar）
+ `--fp32`（副证 `TOL=1e-3`，`compute_dtype=float32` 关混合精度、证明算法数学精确、0.08 不掩盖系统性 bug）。
断言：结构（cu_seqlens + 块对角 mask）、padding vs packing 的 loss 与逐参数 grad `max_abs_error < TOL`。
