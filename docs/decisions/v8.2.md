# V8.2 · 多卡 Megatron（TP × PP × CP）—— 实施与验收

> 状态：**已收官**（2026-08-11）。分支 `v9`。计划见 [v8.2-plan.md](v8.2-plan.md)、执行手册见 [v8.2-kickoff.md](v8.2-kickoff.md)。
> 一句话：**V8 那三条「单卡物理阻断」的偏离（gloo / PP / CP）在 4 卡机上逐条退休**，
> 并且退休是**被逐值证明的**，不是"跑通了就算"。

---

## 1. 做了什么（五刀）

| 刀 | 内容 | 主要文件 |
|---|---|---|
| **1 NCCL** | `backend="nccl"` + device 绑定两种情形都覆盖 | `megatron_trainer.py` |
| **2 重构** | `_microbatch_backward` → `forward_step` + `loss_func` + `get_forward_backward_func()` | 同上 |
| **3 PP** | 1F1B 调度 + **tie 的 embedding 梯度跨 first/last stage 规约** | 同上 |
| **4 CP** | 2-chunk 对称切分 + TE spec + flash 断言 + THD(packing) | `cp_utils.py`（新）+ 同上 |
| **5 转换** | 局部→全局层号 + **PP broadcast**；载权重按 stage 分 | `megatron_to_hf.py` |

**零回归的保证方式**：新参数全 opt-in（`pipeline_model_parallel_size` / `context_parallel_size`
默认 1、`backend` 默认仍 `"gloo"`、spec 默认仍 local、`qkv_format` 默认 `"bshd"`），
V8 的单卡路径数值**逐位不变**（§3 有实证）。

## 2. 三个必须做对的正确性点（都被单独证明了）

### 2.1 loss 数学一行没动，换的是并行轴

`_grpo_sample_loss` 与 V6 torch / V7 FSDP / V8 TP **逐字相同**。V8.2 新增的只有一个参数
`denom`（分母），因为 CP>1 时本 rank 的 `tgt_mask` 只是全量的一部分，分母必须取**全量**
loss_mask 的和 —— 这正是源 `cp_utils.get_sum_of_sample_mean` 的 CP 分支（分子部分和 / 分母全量）。
`cp_size == 1` 时 `denom == clamp_min(tgt_mask.sum(), 1)`，与 V8 恒等。

### 2.2 **跨 rank 的梯度规约有三处，缺一处就"前向对、梯度错"**

这是本版最实质的知识点。三处分别是：

| # | 规约什么 | 通信组 | 源位置 | 漏掉的指纹 |
|---|---|---|---|---|
| 1 | qk-layernorm 梯度（头被 TP 切开，各 rank 是部分和） | TP | `finalize_model_grads.py:402-405` | 最差参数 = `q_norm.weight`（V8 已踩） |
| 2 | **tie 的 word embedding**（输入嵌入与输出投影同一份权重，PP>1 时在不同进程） | embedding group | `finalize_model_grads.py:164` | 最差参数 = `embed_tokens.weight` |
| 3 | **全部梯度跨 DP×CP**（各 CP rank 只持有序列的一部分 token） | dp_cp | mcore DDP 的 `gradient_scaling_factor` | 全体梯度都偏 |

**三者的指纹完全一样**：`loss Δ 恰为 0`，而梯度系统性偏。**只有 fp32 档抓得到**
（V8 已证：漏 #1 时 bf16 的 5e-2 被当舍入放过，fp32 从 1.8e-2 → 1.9e-5，930×）。

> **#3 是本版新发现的**：计划里没有它。它之所以存在，是 V8 偏离 #7（用 torch AdamW 而非
> mcore 的 `DistributedOptimizer`/DDP）的**连带后果** —— 源靠 DDP wrapper 的梯度缓冲自动做，
> nano 没有 wrapper 就没人做。CP=1 时它是 no-op（所以 V8 从没暴露），一开 CP 就必须有。

### 2.3 CP 的序列切分是 **2-chunk 对称**，不是朴素均分

因果 attention 下靠后的 token 工作量随位置线性增长，朴素均分会让最后一个 rank 干最多活。
更要紧的是：**mcore 的 RoPE（`get_pos_emb_on_this_cp_rank`）与 TE 的 ring attention
内部恒按 2-chunk 对称取** —— token 切法不一致就与它们对不上，而形状/dtype/cu_seqlens 全合法，
错得**静默**。G3c 的 negative control 就是把它换成朴素连续切分，实测 cosine 从 0.99921 掉到 **0.588**。

全部用 `--layers 4`（V8 已证等价性与层数无关）。

### 3.3 G3 的证据边界（**必须诚实，不能写过头**）

- **G3a（packing 隔离）有 fp32 逐值精确证明**：`loss Δ=0.000e+00`、`rel_L2=1.890e-07`。
  唯一变量是布局（bshd padding ↔ thd packing），spec/后端/dtype 全相同。
  这与 V7.5 在 FSDP 侧的 fp32 精确证明是同一强度。
- **G3b（CP 本身）只到 bf16 + 反例判别力**：因为 **CP 只有 TE 后端支持 → CP>1 必须 flash →
  FA2 内核只收 fp16/bf16**，fp32 下 TE 直接 `No dot product attention backend is available`（实测）。
  这与 **V7.6 偏离 #8 是同一条物理限制**。
  判别力：正例 cosine `0.99921` / rel_L2 `5.46e-02` vs 反例 cosine `0.588` / rel_L2 `8.12e-01`
  —— rel_L2 差 **14.9×**，cosine 差到不同量级。**反例若"通过"则度量无判别力、整轮验收作废**
  （这条已写进 `_compare(negative=True)` 的逻辑里，不是口头承诺）。
- **不宣称 CP 有 fp32 精确性**。

### 3.4 白捡的一条：**V8 的一处推测被证伪**（kickoff §1.1 预告的那条）

V8 因为装不上 TE 只能用 local spec，在 `all_gather_param` 里给 GLU `fc1` 的
`partition_stride=2` 开了放行，并**猜测**「源用 TE spec 时 fc1 可能不带该 stride，故未暴露」。
本版 TE 装得上了，把两套 spec 各测一遍（一次性探针，TP=2，mcore 0.18.2）：

| spec | `linear_qkv.weight` | `linear_fc1.weight` |
|---|---|---|
| `local` | `partition_stride=1` | `partition_stride=`**2** |
| `transformer_engine` | `partition_stride=1` | `partition_stride=`**2** |

**猜测不成立**：TE spec 下 fc1 的 stride 同样是 2。也就是说源那条无条件
`assert param.partition_stride == 1` 在**它自己的 spec 下也会炸**（至少在 mcore 0.18.2 上），
不是"nano 用了 local spec 才碰到的"。nano 的放行（只对已被 GLU 重排逻辑覆盖的 fc1 放行）
因此是**必需的修正**而非权宜，偏离登记的措辞随之更新。

> 方法学：V8 当时**只能**推测（装不上 TE），把推测**标成推测**写进了注释——
> 于是这一版前提变化后，它是一条可以直接去测的待办，而不是一句被当成事实流传下去的话。

### 3.5 离线全回归

`--offline` 全绿：V0 / V2 / V3 / V4 / V5 / V6 / A1 / A2 / A3 / V7.4。

## 4. 踩的七个坑（都是真调试出来的）

1. **镜像烤入的 `NVTE_*` 与 mcore 的一致性校验冲突**。`fa2-mcore` 把
   `NVTE_FLASH_ATTN=1 NVTE_FUSED_ATTN=0 NVTE_UNFUSED_ATTN=0` 写进了默认 env，而 mcore 默认
   `attention_backend=auto` 期望 1/1/1 → **任何模型都建不起来**
   （`AssertionError: NVTE_FUSED_ATTN set to 0, but expected 1`）。
   初版的修法（nano 自己 set env）是**反的**：mcore 会校验 env 与 config 一致，自己设只会换个地方炸。
   正解 = **显式设 `config.attention_backend`（这正是源传 `--attention-backend` 的落点），
   并在建模型前把继承来的 `NVTE_*` 清掉**，让 mcore 唯一地由 config 决定。
   > 教训：遇到「环境变量与框架打架」时，先找框架**打算**从哪里读这个配置，别在环境侧硬碰。

2. **PP 下 `losses_reduced` 只在 last stage 有值**（mcore schedules 只在那里调 `loss_func`），
   而 rank 0 是 **first** stage → 验收脚本读到 `loss=0`，门红。
   **但梯度本来就是对的**（同一次运行 cosine=1.00000000）。这是"这个数在别的进程里"，
   不是"这个数算错了"。修法 = 把 last stage 的 loss 广播回全组（纯报告用）。
   > 这个坑值得留意：它长得**很像**一个正确性 bug，但指纹不同 —— 真的漏规约是
   > 「loss 对而梯度偏」，这里是「梯度对而 loss 缺」。**先看是哪个数缺失，再判断性质。**

3. **G6 的往返比对必须在 `optimizer.step()` 之前做**。初版放在 `train_batch` 之后，
   报 `max_abs_diff=1.013e-06`（最差 `input_layernorm.weight`），看着像"转换有微小误差" ——
   实际 `1e-6` 恰好就是 `lr`，AdamW 第一步把每个参数挪了大约这么多。**比错了对象。**
   > 数量级本身就是线索：一个"无浮点运算的重排"不可能产生 1e-6 的误差，而它恰等于 lr。

4. **FA2 拒收 fp32** → CP 门不可能有 fp32 档（见 §3.3）。这条在写计划时没预见到，
   是跑出来才知道的 —— 计划 §4 的表格里 G3 那一行写的是 fp32。

5. **mcore 原版 `finalize_model_grads` 调不通**（计划 §1.5 预留的 fallback 真的用上了）：
   它读 `param.main_grad`（DDP 的梯度缓冲）并要 `model_chunk.ddp_config`，
   而 nano 是裸 `GPTModel` + torch AdamW（V8 偏离 #7）。故按同一份逻辑手写、改读 `param.grad`。

6. **`own.get(a) or own.get(b)` 对张量取布尔值**会抛
   `Boolean value of Tensor with more than one value is ambiguous`。必须显式 `is not None`。

7. **tie + PP>1 时 last stage 真的会分配一份 `output_layer.weight`**
   （`pre_process=False` → mcore 不再 skip 分配），且被 `setup_embeddings_and_output_layer`
   填成 0 等着 embedding 组同步。nano 是**建完模型之后**才载 HF 权重，
   必须自己把它填上，否则输出投影全是零 —— **形状全对、不报错**，又一个静默错误。

## 5. 偏离登记（按铁律三要素：源怎么做 / nano 为何偏离 / 语义是否等价）

### 5.1 V8 偏离的处置

| V8 偏离 | 处置 | 说明 |
|---|---|---|
| **#1** gloo 而非 NCCL | ✅ **退休** | 多卡走 NCCL（G1 实测 loss Δ=0、cosine=1.0）。gloo 保留为**单卡多 rank** 的唯一通路（NCCL 硬拒 `Duplicate GPU detected`），故 `backend` 默认仍 `"gloo"` 以护住 V8 回归 |
| **#3** 只做 TP | ✅ **部分退休** | 补 PP（G2/G4）+ CP（G3）。EP 维持不做，理由更新见 5.2-N2 |
| **#4** local spec | ✅ **部分退休** | CP/THD 路径走 TE spec（`get_gpt_layer_with_transformer_engine_spec`，源用的那个）；TP-only 路径仍默认 local spec。实测 TE spec + TP=2 的往返同样 `max_abs_diff=`**0.000e+00** |
| **#6** `_finalize_model_grads` 只做 qk-layernorm | ✅ **部分退休** | 补 embedding 跨 PP（§2.2-#2）+ 全梯度跨 DP×CP（§2.2-#3）。sequence-parallel / MoE router 分支仍不做（未开 SP、无 MoE） |
| **#7** torch AdamW 非 `DistributedOptimizer` | 维持 | 它是 ZeRO-1 式优化器状态分片，属"省显存"不属"并行语义"。**但连带成本在本版显形**：见 5.2-N5/N6 |
| **#11** 权重同步止于转出 HF state_dict | 维持 | 但 G6 把 **PP broadcast** 补进了转换路径（源 `hf_weight_iterator_direct.py:66-77`）—— V8.1 只见到这条 RL 接缝的一半 |

### 5.2 本版新增偏离

| # | 偏离 | ①源怎么做 | ②nano 为何偏离 | ③语义是否等价 |
|---|---|---|---|---|
| **N1** | 不做 VPP / interleaved 1F1B | 源支持 `virtual_pipeline_model_parallel_size` | 它是**减 bubble 的调度优化**，不改 PP 语义；4 卡 2 stage 的 bubble 本就不严重 | 等价（PP 语义相同），吞吐不等价 → 留 V9 作旋钮 |
| **N2** | 不做 EP | 源对 MoE 开 `expert_model_parallel_size` | **Qwen3-0.6B 是 dense 模型，没有 expert** —— 不是做不到，是无对象（V8 写的"gloo 无 all_to_all"已作废） | 不适用 |
| **N3** | **CP>1 硬断言 flash 后端** | 源所有 megatron 脚本的 `MISC_ARGS` 都带 `--attention-backend flash`（`run-qwen3-4B.sh:139`），`debug.md:15` 说明理由是"避免 CP 下 fused attention 的数值不稳定" | 不偏离——nano 是把源的**隐式配置约定改成显式断言**，因为 sm_120 上落到 fused 会**静默算错**（实测 dq cosine 0.356，TE#3333），源在 Hopper 上只是"不稳定"、这里是确定错 | 完全等价，只是把配置约定编码进代码 |
| **N4** | CP 门只到 bf16 + negative control | 源不做这类等价验收，直接信内核 | **FA2 内核拒收 fp32**（实测 `No dot product attention backend is available`），而 CP 只能走 flash | **不完全等价**：未证 fp32 精确。承 V7.6 偏离 #8 的同一条边界。packing 部分（G3a）另有 fp32 精确证明 |
| **N5** | `_finalize_model_grads` 手写而非调 mcore 原版 | 源 `model.py:539` `config.finalize_model_grads_func = finalize_model_grads`（mcore 原版） | 原版读 `param.main_grad` 且要 `model_chunk.ddp_config` —— 裸 `GPTModel` + torch AdamW 没有这两样（偏离 #7 的连带后果） | 等价（同一份逻辑，改读 `param.grad`），覆盖面窄（只做 qk-layernorm + word embedding 两条分支） |
| **N6** | 手写 DP×CP 梯度 AVG 规约 | 源靠 mcore DDP 的梯度缓冲自动做（`gradient_scaling_factor=1/dp_cp`） | 同 N5：无 DDP wrapper 就没人做这一步 | 等价（`loss × dp_cp` 的缩放 + AVG 规约 = 各 rank 贡献求和，与源净效果相同）；性能不等价（无 bucket/overlap） |
| **N7** | 不实现 `get_logits_and_tokens_offset_with_cp` / `get_sum_of_sample_mean` 的 CP 分支 | 源用它们在全局坐标里定位 response 段的 logits，并修正 loss 分母 | nano 改用**等长 full 坐标系**：把 targets/mask/old_log_probs 都物化成与 token 流等长的数组（位置 g ≡「logits[g] 预测 tokens[g+1]」），再用**同一个** `slice_with_cp` 切 | 等价（源的 offset 算的就是这套对齐；源 `data.py:137` 的 `F.pad(loss_mask, (prompt_length-1, 1))` 是同一件事），且少一处易错的下标算术 |
| **N8** | PP 下把 last stage 的 loss 广播回全组 | 源在 last stage 上记日志（`loss.py:431` / `model.py:279` 都有 `is_pipeline_last_stage` 守卫） | 让任一 rank 都能报同一个数，验收脚本不必关心自己是哪个 stage | 等价（纯报告用，不进梯度路径） |
| **N9** | 建模型前清掉继承来的 `NVTE_*` | 源不碰 env（只传 `--attention-backend`） | 容器镜像把 `NVTE_*` 烤成了默认值，与 mcore 的一致性校验冲突（§4-1） | 等价（清掉后由 mcore 按 config 唯一决定，正是源的效果） |
| **N10** | 不接 Ray 闭环 | 源的 megatron 后端跑在 Ray actor 里 | 维持 V8 拍板：与 V7.3（FSDP + Ray）高度同构，铺开只是重复 | 等价（并行语义与调度框架正交），本版用 `torchrun` 验收 |
| **N11** | 只用一个 model chunk（`model=[self.model]`） | 源在 VPP 下传多个 chunk | 不做 VPP（N1），单 chunk 即全部 | 等价（`pp_size>1 且无 VPP` 时源也是单 chunk） |
| **N12** | THD 的 `cu_seqlens` 逐条按全局长度累加 | 源 `data.py:112` 写 `cu_seqlens * cp_size` | 各条样本的 CP padding 量不同，逐条算全局长度比整体乘更不易错 | 等价（`cp_padded_length` 用的是与 `slice_with_cp` 同一个 chunk_size 公式） |

## 6. 暴露的痛点 → 接什么

**V8.2 之前的八版全在问「对不对」，到这一版为止答案是清楚的**：TP/PP/CP 三根轴、
两种布局、两套 spec、两个通信后端，都有逐值证据。**下一版第一次问「多快」** ——
[V9 吞吐实验](v9-plan.md)。

V8.2 直接为 V9 交付了三件前置：

## 收官后附记：TE 2.18 修复 TE#3333（2026-08-16 实测）

**背景**：V8.2 偏离 N3「CP>1 硬断言 flash 后端」的理由是 TE#3333——cuDNN fused attention 在
sm_120 + THD + backward 下静默算错（dq cosine 0.025–0.44）。2026-08-14 TE 发布 v2.18，
commit 70957ad5 修复了该 bug（softmax stats 前向按 `[num_tokens, h, 1]`、反向按 `[b, h, s, 1]`
的 layout mismatch）。在 te218-probe 容器（TE 2.18 + FA2 2.8.3 + cuDNN 9.25）上实测结果：

| 测试 | TE 2.17 | TE 2.18 |
|---|---|---|
| issue #3333 repro，fused，q_grad_cos | 0.025–0.44 ❌ | **1.0000 ✅** |
| G3b CP=2 flash（V8.2 现用）cosine | — | **0.99921 ✅** PASS |
| G3b CP=2 fused（TE 2.18）cosine | — | 0.99894 ❌（差门 0.001）|
| G3c 朴素切分 negative control cosine | — | 0.604 ✅ 判红 |

**结论**：

- TE#3333 已不存在。fused CP=2 的 cosine（0.99894）远离 negative control（0.604），
  差 flash（0.99921）仅 0.001——这是 cuDNN 与 FA2 两个内核在 ring attention 里积累的
  bf16 舍入差，不是正确性缺陷。
- **偏离 N3 理由更新**：原因从「fused 算错」改为「对齐源项目约定（源用 flash）且 flash
  过门更干净」，代码注释已同步更新（`megatron_trainer.py:243`）。决策不变，理由升级。
- **fp32 门仍不可达**：fused 和 flash 均拒收 fp32（实测 `No backend available`），
  unfused 接受 fp32 但不支持 CP。偏离 N4「CP 门只到 bf16 + negative control」维持不变。
- **G3a 在 TE 2.18 下的阈值**：跨内核（sdpa bshd vs fused/flash thd）bf16 比对 cosine
  落在 0.998–0.999，比原版（fp32 unfused 两边同内核 Δ=0）低——这是跨内核舍入，不是退步。
  原版 G3a 用 `--fp32`（强制两边 unfused 同内核），是正确做法；V9 沿用。
