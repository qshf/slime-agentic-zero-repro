## 2. 两个教学核心

### 2.1 换一根并行轴（同一份 loss 数学）

| | V7 FSDP | V8 Megatron TP |
|---|---|---|
| 切什么 | 参数**存储**按 rank 分片 | 参数**计算**按行/列切 |
| 前向 | all-gather 回全量层再算 | **不 gather**，各 rank 算部分结果 + all-reduce |
| 通信位置 | 层边界（gather 参数） | **层内部**（col→row 之间 all-reduce 激活） |
| 边界 | 单层须放得下一张卡 | 单层也可跨卡 |

`_grpo_sample_loss` 与 V7 `FSDPTrainer._grpo_sample_loss` **逐字相同**——V8 换的是并行轴，不是 loss 语义。

**vocab-parallel logits**：源 `model_provider.py:177` 设 `parallel_output=True`，输出层按 vocab 切，
各 rank 只有 `[S, V/tp]` 分片，**从不 gather 成全量**（V=151936，gather 白吃显存+通信）。
故 log_prob 必须走 `fused_vocab_parallel_cross_entropy`（内部跨 TP 组 all-reduce max 与 sum-exp）。
实测它与全量 log_softmax 的 `max_abs_err = 0.000e+00`。

### 2.2 Megatron→HF 权重转换（**slime-agentic 相对纯 Megatron 教程的真正增量**）

FSDP 的 `save_pretrained` 天然吐 HF 格式（V6/V7.3 的 disk reload 就靠它）；
**Megatron 的参数名和形状都不是 HF 的**——`linear_qkv.weight` 是 qkv 融合、还按 TP 切开的。
要同步回 SGLang 必须先 **TP-gather + 拆 qkv/gate + 改名 + 去 vocab padding**。
源为此写了整个 `megatron_to_hf/` 目录（10 个模型各一份）+ `update_weight/`（2232 行）。

三处最易错、都单独立了断言：
1. **GLU 重排**（`all_gather_param`）：fc1 是 `[gate; up]` 整体按 TP 切，rank r 手里是 `[gate_r; up_r]`。
   朴素 `cat` 拼成 `[gate_0, up_0, gate_1, up_1]` —— **错**，正确是 `[gate_0, gate_1, up_0, up_1]`。
2. **qkv 按 `num_query_groups` 拆 GQA**，**不是**沿 dim0 三等分（每个 KV group 的 q 头与其 k/v 相邻）。
3. **名字集合双向比对**（缺失 + 多余）——源那 10 个转换文件最常见的 bug 类型正是漏/多一个名字。

## 3. 验收结果（5090 单卡，`torchrun`）

### V8.0 TP 等价（**分层 gate**，沿用 v7.5.md 度量教训）

| 档 | 层数 | loss Δ | grad rel_L2 | grad cosine | 判定 |
|---|---|---|---|---|---|
| **fp32（精确证明）** | 4 | **0.000e+00** | **1.935e-05** | **1.00000000** | ✅ 硬门（rel_L2<5e-3 且 cos>0.9999） |
| **fp32（精确证明）** | **28（全模型）** | 4.023e-07 | **1.035e-05** | **1.00000000** | ✅ 同上 |
| bf16（训练实际 dtype） | 4 | 5.066e-06 | 5.088e-02（info） | 0.99908911 | ✅ 硬门（loss + cos>0.999） |

> **为什么分层**：TP 是数学恒等切分，fp32 下误差只剩 all-reduce 规约顺序；bf16 在 28 层前向里
> 舍入会累积到 rel_L2 几个百分点，那**不是 TP 切错**。判别力仍在——真切错是 O(1) 级、cosine 掉到 0.x
> （见 §4 那次 dropout 假阳性实测 cosine=0.25）。

> **全 28 层也过**（v8-plan §7「先缩减层数再冲全层」的后半程已完成）——**等价性确实与层数无关**，
> 缩减层数只是为了快和省显存。**踩到一个测试侧的坑**：初版把 310 个梯度 `cat` 成一条 float64 大向量
> 要 ~10GB，本机只有 15G RAM → full-28 被 OOM kill（日志停在形状检查后、无报错行）。
> 改成**逐张量累加** Σ|a-b|²/Σa·b/Σa²/Σb² 四个标量（数学等价，全局 L2/cosine 本就只依赖它们）后过。

### V8.1 转换（TP=1 / TP=2 / 全 28 层都跑）

## 4. 三个踩坑（都是本版真实调试出来的）

### 坑 1 · dropout 未关 → 等价门假阳性（`cosine=0.25`）

`TransformerConfig` 的 `hidden_dropout`/`attention_dropout` **默认 0.1**，而
`model_parallel_cuda_manual_seed` 会**故意**让各 TP rank 持不同的 dropout RNG（TP 区域内 dropout
本就该各切片独立）。于是 TP=1 与 TP=2 丢弃的是不同单元 —— 实测 grad cosine 只有 **0.25**、
grad_norm 差 11×，而这**不是 TP 切错，纯粹是随机性**。
修：显式 `hidden_dropout=0.0, attention_dropout=0.0`。这同时也更**忠实**——HF Qwen3 config 的
`attention_dropout=0.0` 且无 hidden dropout，继承 Megatron 的 0.1 等于凭空改了模型；RL 微调也从不开 dropout。

### 坑 2 · fused kernel 原地改输入 → fp32 才暴露的 autograd 报错

`fused_vocab_parallel_cross_entropy` 会 **in-place** 减去 max（`vocab_parallel_logits -= logits_max`）。
nano 逐样本切 `logits[row, :L-1]`，各样本切片**共享同一块 base storage** → 撞上 autograd 版本计数
（`modified by an inplace operation ... is at version 9; expected version 6`），且会污染产生 logits
那一步自身的反向。
**bf16 时 `.float()` 恰好隐式拷了一份把问题盖住，只有 fp32（`.float()` 是 no-op）才暴露。**
修：显式 `.float().clone()`。源不需要这一步——它把整批 pack 成一条 `[S,B,V]` 一次性喂进 kernel，不做逐样本切片。

> 教训与 V7.6 同型：**换一档精度做副证，会顺带体检出主路径掩盖的真 bug**。

### 坑 3 · 漏 `finalize_model_grads` → qk-layernorm 梯度是部分和（**本版最实质的正确性发现**）

fp32 下 loss Δ **恰为 0**（前向逐值相同），grad 却有 `rel_L2=1.8e-2`，且逐参数最差的是
`q_norm.weight` —— 「前向精确相同、梯度却有系统性偏差」正是**漏规约的指纹**。

根因在源里写着：`megatron/core/distributed/finalize_model_grads.py:403-405`
（`_allreduce_non_tensor_model_parallel_grads`）对
`config.qk_layernorm and ("q_layernorm" in name or "k_layernorm" in name)` 的参数做
**SUM** all-reduce。因为 q/k-layernorm 作用在**每个头**上，而头被 TP 切开 —— 各 rank 只见自己那份头，
算出的梯度是**部分和**，加起来才是全量。其余 layernorm 不需要：它们在 TP 区域**外**，
输入是各 rank 相同的全量激活（row-parallel 的 all-reduce 保证反向传回的梯度也相同）。

修：`MegatronTrainer._finalize_model_grads()`，在累积循环之后、clip/step 之前调用（与源同位置，每 step 一次）。
**效果：rel_L2 1.801e-02 → 1.935e-05（约 930×），cosine 0.99984 → 1.00000000。**

> 这条坑单靠 bf16 抓不到（5e-2 会被当成舍入放过）——**fp32 副证的价值就在这里**。

## 5. 不实现的三轴 · 概念笔记（按铁律「记录设计」）

| 轴 | 源怎么做 | 单卡为何做不了（实测） | 补齐条件 |
|---|---|---|---|
| **PP** 流水并行 | 按层切 stage，stage 间 **NCCL p2p** 传激活，1F1B 调度掩 bubble；`mpu.is_pipeline_first_stage/last_stage` 门控 loss 只在最后 stage 算（`model.py:279,463`） | 实测 7：gloo 不支持 CUDA p2p（`gloo::IoException writev Bad address`）。经 CPU 中转虽可传，但既慢又**偏离源**——假装做等于教错 | ≥2 卡 + NCCL |
| **CP** 上下文并行 | 按 seq 维切，attention 处 all-gather / ring 交换 KV（`cp_utils.py:slice_with_cp`）；与 V7.5/V7.6 的 packing 正交但会组合（THD layout） | 单卡 CP=1 等于没开，无可验内容 | ≥2 卡 |
| **EP** 专家并行 | 按 expert 切，**all_to_all** 路由 token（`expert_model_parallel_size`） | 实测 9：`Backend gloo does not support alltoall` —— **物理不可做**；且 Qwen3-0.6B 是 dense 无 expert | ≥2 卡 NCCL + MoE 模型 |

## 6. 偏离登记（按铁律三要素：①源怎么做 ②nano 为何偏离 ③语义是否等价/何时补齐）

| # | 偏离 | ①源怎么做 | ②nano 为何偏离 | ③等价性 / 何时补齐 |
|---|---|---|---|---|
| **1** | **通信后端 gloo 而非 NCCL** | 源用 NCCL（`initialize.py`） | 单卡多 rank 被 NCCL 硬拒（实测 `Duplicate GPU detected: rank 0 and rank 1 both on CUDA device 80`），gloo 是单卡跑多维并行的**唯一通路** | **集合通信语义等价**（结果相同），**性能不等价**（gloo 走 TCP）。V8 教并行语义**不测吞吐**（吞吐留 V9）。多卡时传 `backend="nccl"` 即可 |
| **2** | **只用 `megatron.core`，不走 `megatron.training.init`** | 源 `initialize.py:init` 走 training 路径（含 `_build_tokenizer`/微批计算器等训练框架件） | nano 只需并行组 + GPTModel；且源 `initialize.py:66` 断言 `numpy 1.x`，容器是 2.3.5 | 语义等价（并行组由同一个 `mpu.initialize_model_parallel` 建）。朝**更清晰**偏离（少一层用不上的框架） |
| **3** | **只做 TP，PP/CP/EP 记录设计不实现** | 源支持 TP/PP/CP/EP 全维 | 实测硬阻断：PP 需 CUDA p2p（gloo 不支持）、EP 需 all_to_all（gloo 无）、CP 单卡=1 无内容。见 §5 | **不等价**（少三根轴）。**偏离有实测依据不是偷懒**；接缝按源留好（`pipeline_model_parallel_size=1` 显式传参），租到 ≥2 卡 + NCCL 可直接补 |
| **4** | **layernorm 用 local spec 命名（`input_layernorm` / `pre_mlp_layernorm`）** | 源用 TE spec（`get_gpt_layer_with_transformer_engine_spec`），layernorm 被**融进**后继 linear 的 `layer_norm_weight`（故源 `qwen2.py:60-63` 只认这两个名字） | 容器装 FA2 后 TE import 会崩（见 v7.6.md 环境三坑），故用 `get_gpt_layer_local_spec` | **数学完全等价**（同一个 RMSNorm，只是挂载位置不同）。转换函数**两种名字都认**（源的名字保留=忠实，local 的名字=nano 实际用的），`load_hf_into_megatron` 按模型真实参数名**自动判定**不靠猜 |
| **5** | **`partition_stride=2` 对 GLU fc1 放行** | 源 `all_gather_param` **无条件** `assert param.partition_stride == 1`，然后**再**按名字给 `linear_fc1` 做 GLU 重排 | 实测（megatron-core 0.18.2 + local spec）`linear_fc1.weight` 的 `partition_stride` **就是 2**，照搬源的断言会在 TP>1 直接炸。stride=2 正是 Megatron 表达「[gate; up] 交错切分」的元数据，而源那段 `chunk(2)→[gates...,ups...]` 重排**恰恰就是 stride=2 的解包逻辑**——**源的断言与它自己的重排分支语义冲突**（源用 TE spec 时 fc1 可能不带该 stride 故未暴露） | **语义等价于源的意图**（重排后就是全量 `[gate; up]`）。nano **只对已被重排逻辑覆盖的 GLU fc1 放行 stride=2，其余仍严格 ==1**——不放过真正没处理的 stride 情形 |
| **6** | **`_finalize_model_grads` 只做 qk-layernorm 一条分支** | 源 `finalize_model_grads.py:402-405` 是并列两条：`(config.sequence_parallel and param.sequence_parallel)` **或** `(config.qk_layernorm and q/k_layernorm in name)`；还含 embedding/router/条件 embedding 的规约 | nano 未开 sequence parallel（那条恒 False）、无 MoE router、PP=1 故无跨 stage embedding 规约 | **在 nano 的配置下语义等价**（其余分支恒不触发）。开 SP/MoE/PP 时须补 |
| **7** | **优化器用 torch AdamW，非 Megatron `DistributedOptimizer`** | 源用 `DistributedOptimizer`（ZeRO-1 式优化器状态分片） | 它与 TP **正交**（是另一根省显存的轴），铺开会冲淡本版「层内切分」的教学主线 | **梯度/更新数学等价**（同一个 AdamW），**显存不等价**（优化器状态未分片）。要补另开一版 |

## 7. 暴露的痛点 / 后续

- **gloo 慢**：TP 每层两次 all-reduce 走 TCP。本版**明确不做吞吐断言**——吞吐留 V9。
- **PP/CP/EP 三轴需要真多卡**：接缝已按源留好（显式 `pipeline_model_parallel_size=1`），
  租到 ≥2 卡 + NCCL 可直接补 §5 的设计。
- **packing × TP 的组合（THD layout）** 未做：V7.5/V7.6 的 packing 在 FSDP 路径，与 TP 正交但会与 CP 耦合。
