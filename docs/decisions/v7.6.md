## 2. 实施：三处改动（loss 数学一行未动）

### 2.1 `train_packing` 三态化（`mini_slime/args.py` + `_normalize_packing_mode`）

| 值 | 路径 | 定位 |
|---|---|---|
| `False`/`""`（默认）| padding：逐样本一行 `[B,L]` | V7.0/V7.2 路径，零回归 |
| `"fa2"` | flat `[1,T]` + `attention_mask=None`，varlen 内核隔离 | **对齐源**，V7.6 新增 |
| `"mask"` | flat `[1,T]` + 显式块对角 4D mask | V7.5 路径，降为 fallback |

`True` 归一到 `"mask"`（V7.5 布尔语义兼容，旧调用点零改动）。非法值抛 `ValueError`。

### 2.2 `attn_implementation` 参数（补齐源缺失参数）

`FSDPTrainer.__init__` 的 `from_pretrained` 加 `attn_implementation=`，**对齐源 `actor.py:96`
（`attn_implementation=self.args.attn_implementation`）+ `arguments.py:29`（源默认 `"flash_attention_2"`）**。
nano 默认 `"sdpa"` 而非源的 FA2：V7.0–V7.5 环境无 FA2，且 `"mask"` packing 要求 eager/sdpa
（4D mask 只在这两个后端被当加性 bias）。`train_packing="fa2"` 时须显式设成 `"flash_attention_2"`，
硬断言会拦截不匹配（见 §2.4）。

### 2.3 `_packed_backward` 的前向分支（唯一实质改动）

段切分与 loss 计算**一行未动**——`logits[start:end-1]` 预测 `tokens[start+1:end]`、
`_grpo_sample_loss` 共用，这是三路（padding/mask/fa2）等价的根本。只换「怎么喂前向」：

```python
# "fa2"（对齐源 actor.py:801-812 _get_model_inputs_args）
logits = self.model(input_ids,               # [1,T]
                    position_ids=position_ids,  # [1,T] 每段 reset —— 既定位 RoPE 又定义段边界
                    attention_mask=None)        # 源逐字对应
```

`pack_sequences` **完全不动**（flat + reset position_ids + cu_seqlens 全部照用）。注意 fa2 模式下
`cu_seqlens` 不再喂给内核（transformers 从 position_ids 反推），退化为**切 loss 段 + 验收对照**用。

### 2.4 三重硬断言（本版最危险失败模式的防线）

fa2 路径传 `attention_mask=None`，一旦任一环节没到位就是**静默**满因果注意力 → 段间串扰 → loss 悄悄算错
（比 crash 危险得多）。故：

```python
assert attn_impl == "flash_attention_2"      # 后端不对 → None mask 落到 eager/sdpa = 满因果
assert is_flash_attn_2_available()           # flash-attn 没装/版本不符
_assert_varlen_will_engage(position_ids, n)  # position_ids 真被判成 packed
```

**第三条不自己写单调性判据，而是直接调上游 `_is_packed_sequence`**
（`modeling_flash_attention_utils.py:528-541`）。理由：varlen 是否启用完全由上游那个函数说了算，
自己另写一套"看着等价"的判据，一旦与上游不一致就会出现**断言通过但 varlen 没启用**的最坏情况。
上游不可导入时才退回镜像其语义的 diff-based 实现（非"严格递增"）。

**长度=1 的段不会误判**（review 时提出的点，已实测验证）：pack 的 position_ids 每段从 0 重数，
段边界 diff = `0 - (L_prev - 1) = 1 - L_prev`，等于 1 仅当 `L_prev == 0`（空段，`pack_sequences`
的 `len>=2` 过滤根本产生不了）。`L_prev == 1` 时 diff = 0 ≠ 1 → 照样被检出。实测覆盖
`[1,1]`/`[3,1]`/`[1,3]`/`[1,1,1,1]`/`[2,1,2]` 全部正确判为 packed；单段 `[7]` 正确判为非 packed
（无段可隔离，退化成普通因果前向是正确语义，故 `num_segments<=1` 直接放行）。

## 3. 验收范式：为什么不能用 V7.5 的 fp32 硬门

**FA2 内核只接受 fp16/bf16**，实测：
```
RuntimeError: FlashAttention only support fp16 and bf16 data type
```

这直接废掉了 V7.5 的正确性论证基础。V7.5 的结论是「**fp32 才是精确证明、bf16 只到舍入**」——
bf16 下 28 层前向的舍入累积让 grad magnitude rel_L2 达 10.9%（已确认是舍入非 bug），
**单看误差大小无法区分"隔离正确"与"隔离失效"**。fa2 路径拿不到 fp32，等于失去那个硬门。

### 替代：negative control（用判别力代替精度）

不追求"误差足够小"，改为证明**度量本身能把正确与泄漏分开**。反例构造极简——把每段 reset 的
position_ids 换成全局单调递增，上游 `_is_packed_sequence` 立刻返回 False，varlen 不启用，
整个 pack 退化成一条长序列（**真串扰**）。这正是 fa2 路径最危险的静默失败模式。

实测判别力（Qwen3-0.6B 全 28 层，4 条真样本 T=80，bf16，参照 = padding 路径）：

| 组 | loss \|Δ\| | grad rel_L2 | grad cosine |
|---|---:|---:|---:|
| **正例**（reset position_ids） | **0.000e+00** | **1.330e-04** | **0.99999999** |
| **反例**（单调 position_ids = 泄漏） | 1.435e-02 | 1.160e+00 | 0.41475487 |

**判别力 8721×**。正例与反例隔着 4 个数量级，门槛站得住。

> **反例若"通过"等价断言，则度量无判别力、整轮验收作废**——这条写进了测试逻辑。它顺带堵了
> infra doc 04 §3b.4 记录的那类假阴性（"绝对阈值 + 无对照 → 错误梯度蒙混过关"）。

### 证据边界（诚实声明，不写过头）

- **fp32 逐值精确证明只属于 `"mask"` 路径**（V7.5：loss 2.4e-7 / cosine 0.99999999），本版回归复验仍绿。
- **fa2 路径自身的证据 = negative control（8721×）+ 与 padding 路径 bf16 逐值一致（loss Δ=0、cosine 0.99999999）**。
  **不宣称 fa2 继承了 mask 路径的 fp32 精确性**——两路走不同内核，bf16 一致不等于 fa2 也被 fp32 验证过。
  这是登记偏离 #8 的原因。

`bench5090` 常驻容器**不能直接用**，必须临时容器 + 三步修正：

```bash
docker run --rm --gpus all -v /root:/host:ro \
  -v /root/slime-agentic-zero-repro:/workspace/slime -w /workspace/slime \
  agentic-rl-infra-lab:te-cudnn-system-spike bash -lc "
    pip uninstall -y flash-attn-4                                  # ① namespace 被 FA4 b15 占
    pip install --no-deps -q /host/flash_attn-2.8.3+cu13torch2.10cxx11abiTRUE-cp312-cp312-linux_x86_64.whl
    pip install -q accelerate                                      # ② 容器缺，FSDPTrainer 起不来
    NANO_MODEL_PATH=/host/models/Qwen/Qwen3-0.6B \
      torchrun --nproc_per_node=1 scripts/test_v7.6_fa2_packing.py"
```

① `import flash_attn` 会成功但**无 `__version__`**（那是 FA4 的包）；② `accelerate` 是
`get_init_weight_context` tie 分支的依赖；③ **wheel 不能单文件 bind mount**（挂载改名破坏 wheel
命名规则 → `Invalid wheel filename`），必须挂目录用原始文件名。

> 装完 FA2 后 **TE import 会崩**（覆盖 `flash_attn` namespace，TE `backends.py` 无条件 import
> FA4 的 `cute.interface`）→ 务必 `--rm` 临时容器，别污染 `bench5090` 的 TE 对照环境。

## 7. 教学要点

1. **`position_ids` 是双职**：既定位 RoPE，又**定义段边界**。varlen 路径下它是唯一的隔离信息来源
   （`attention_mask=None`），所以"每段 reset"从 V7.5 的锦上添花变成 V7.6 的**正确性必需**——
   写错就是静默串扰。这是 `_assert_varlen_will_engage` 存在的理由。
2. **同一份 loss 数学，三种前向后端**：padding `[B,L]` / 块对角 mask `[1,T]` / varlen `[1,T]`，
   `_grpo_sample_loss` 一字不改。等价断言能成立正是因为这份共用。
3. **没有 fp32 时怎么证正确**：不是降低门槛，而是换证明方式——**证度量有判别力**（正例 vs 故意
   泄漏差 4 个数量级），比"误差小于某个拍脑袋的绝对值"强得多。V7.5 的度量教训（全局 rel_L2 +
   cosine 而非逐参数 max）与本版的 negative control 是同一件事的两面：**先确认度量能测出你要测的东西**。
