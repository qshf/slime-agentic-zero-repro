## Context（为什么做 A2）

A1 MemAgent 的 loss_mask **全 1**（单引擎、无工具），教不了"模型输出 vs 工具返回"的**训练边界**——这是
README 问题 #2 的精华课。A2 = **AgentFlow**，引入 **Planner→Executor→Verifier** 多角色 ReAct 循环。

**教学核心（路线图钦定）= "executor token 不训练"**：
- **只有 Planner** 的 `plan()` / `generate_next_step()` 成为训练序列（`loss_mask=1`）；
- **Executor（生成工具命令 + 执行工具）/ Verifier（判 STOP/CONTINUE）/ final_output** 的生成 token
  **完全不进 training turns**——它们是"环境"，交给**固定引擎**跑，对 loss 零贡献。

这正是源在系统层的落地：**不训练的角色，交给一个不会变权重的固定引擎**；训练引擎只跑 planner 这个真正
要优化的策略。reward 相比 A1 的纯 boxed，新增 **LLM-as-judge 回退**（boxed miss 时固定引擎判官）。

## 做了什么

**新增（镜像源 `agentic/agentflow/`，各文件 1:1 对齐角色）**：
- `toy_rl/agent/agentflow/memory.py`：`Memory`（action dict，几乎照搬源 `core/memory.py`）。
- `planner.py`：`Planner`——`plan` / `generate_next_step`（训练引擎，进 turns）+ `generate_final_output`
  （显式收固定引擎 chat_fn，不进 turns）。prompt 模板从源逐字搬。
- `executor.py`：`Executor`——`generate_tool_command`（固定引擎产 `tool.execute(query=…)`，正则抽 query）
  + `execute_command`（分发给复用的 `ToolRegistry`）。
- `verifier.py`：`Verifier`——`verificate_context` → `parse_conclusion`（照搬源 STOP/CONTINUE 解析）。
- `rewarder.py`：`Rewarder`——`compute_reward`（固定引擎判官 `VERDICT: True/False`，照搬源解析）。
- `solver.py`——**本版的星**：`Solver.solve` 编排 ReAct 循环，**只把 planner 两类调用 `_emit_turn`**
  （loss_mask=1），拼接进 sample。`extract_context_subgoal_and_tool`（源 formatters）折进本文件。
- `rollout.py`——薄适配器：造双引擎两个真 SGLang chat_fn → 组装 Solver → 回填 Sample；`reward_func`
  （boxed 精确匹配 + `Rewarder` 回退）。boxed/is_equiv/strip_think 复用 A1 memagent.rollout。
- `data.py`：4 条硬编码算术 QA（`{prompt,label}`，calculator 能解、label 可 boxed 命中）。
- `stub_rollout.py`：离线 no-SGLang stub，复用**同一个** `_build_solver`/`Solver.solve`，注入两个造假
  chat_fn（planner 产可解析的 Context/Sub-Goal/Tool Name；fixed 产 `tool.execute` + STOP + `\boxed{label}`）。
- `scripts/test_a2_agentflow.py`：不变量 1-5（多轮结构 + executor token 不训练 + 只有 planner 进 turns
  + boxed reward + 闭环）。

**改动（都朝"更对齐源 + 零回归"方向）**：
- `mini_slime/args.py`：加 A2 专属字段 `af_planner_base_url/af_planner_model/af_fixed_base_url/
  af_fixed_model/af_max_steps=3/af_max_tokens=512`（仅 agentflow 路径读；calculator/memagent 不受影响）。

## 与 A1 MemAgent 的关键差异（A2 新引入的）

| 维度 | MemAgent（A1） | AgentFlow（A2） |
|---|---|---|
| 引擎 | 单引擎 | **双引擎**（训练 planner / 固定 executor·verifier·final_output） |
| 角色 | 只有 LLM 自己 | **Planner→Executor→Verifier** 多角色 ReAct |
| 工具 | 无工具 | calculator（executor 生成命令→分发执行） |
| loss_mask | response 全 1 | **只有 planner 进 turns**；executor/verifier/final_output 根本不进 → 对可训练 token 零贡献 |
| reward | boxed + is_equiv | boxed + **LLM-as-judge 回退**（固定引擎判官，reward 稳定） |
| 多轮 | N 条独立记忆对话 | 1 plan + K next_step（每条独立训练序列） |

## 偏离登记（按铁律三要素）

| 偏离点 | ①源怎么做 | ②为何偏离 | ③等价性/何时补齐 |
|---|---|---|---|
| **固定引擎默认与训练引擎同端点(30001)** | 源 executor/verifier/final_output 走独立 30000 端点 | 0.6B 跑 judge/final_output 太弱、reward 不稳；nano 保 reward 可用 | **角色仍分两引擎**（Args 两字段 + engine_map 两 chat_fn），loss_mask 边界与端点无关；服务器把 `af_fixed_base_url` 指 30000 即成两真实引擎 |
| **单玩具工具(calculator)** | 源 base_generator(LLM) + python_coder(子进程) | 多工具/子进程执行是仪式，淹没"executor token=0"这堂课 | 角色等价（executor 生成命令→分发执行）；多工具留后续 |
| **executor 命令解析只留正则** | 源三级(exec/正则/贪婪) + `_extract_command` 剥代码块 | nano 命令格式固定简单；exec 执行有安全面且淹没重点 | 主流程等价（都从命令抽出 query） |
| **Solver 收 chat_fn 而非 engine_map** | 源 Solver 收 engine_map(6 键→2 引擎)、内部构造各角色 | nano 直接收造好的角色 + fixed_chat_fn；双引擎语义落在 rollout 造 chat_fn 处 | 语义等价（都是"planner 走训练引擎、其余走固定引擎"） |
| **字符级假 token / 无真 log_probs** | /generate 真 tokenizer + log_probs | 沿用 V1-V5/A1 | loss_mask 构造等价；真 tokenizer 留 V6 |
| **硬编码算术 QA** | prepare_data 生成数据集 | 只需跑通闭环 | 结构等价（prompt/label） |
| **reward 归一化取最简 / 不做 turn 均摊** | 完整 `_strip_string` / custom_convert 均摊 | 同 A1（路线图 / fake trainer） | 主流程等价；credit 分配留主线三 |
| **formatters 折进 solver** | 源独立 `core/formatters.py` | 仅 solver 用，独立成文件是仪式 | 语义等价（同一函数） |

## 测试为什么仍用同步 train_ray（同 A1）

`test_a2_agentflow.py` 的 `test_closed_loop` 调 `train_ray.py`（同步，≡ 源 train.py），不用 `train_async.py`。
理由与 A1 完全一致（见 a1.md「测试为什么用同步」一节）：train_ray 与 train_async 对 agent 等价、唯一区别是
gen(N+1) 的调度时机；异步正确性 + overlap 已由 V5 的 `test_v5_async.py` 专门担保。A2 只需验证 AgentFlow 产的
样本形态（loss_mask 边界 / turns 结构 / reward），用同步版是更干净的载体。

## 实际结果（2026-07-23，本地离线）

`python scripts/test_a2_agentflow.py --offline` → **PASSED**：
```
[What is 37 * 24?] turns=2 tokens=2034 trainable=241
  final_output='The computation is complete. \boxed{888}' pred='888' reward=1.0
single_sample OK
[rollout 0] gen=0.176s train=0.0006s sync=0.0003s | reward_mean=1.000 tokens=4080 weight_v=2
closed_loop OK
```
- **多轮结构**：turns=2（1 plan + 1 next_step；stub verifier 首步即 STOP）。
- **executor token 不训练不变量**：每轮 `loss_mask == [1]*response_length`；trainable=241 = 各 planner turn
  response 之和；tokens=2034 含各 planner turn 的 prompt 前缀（loss_mask=0）。**executor/verifier/final_output
  的生成文本进 `sample.response`（供日志/reward）但不进 tokens** —— 由 `sum(loss_mask)==sum(response_length)`
  + `turns 全为 kind=="planner"` 双重断言保证。
- **boxed reward**：final_output `\boxed{888}` 抽取命中 label → reward=1.0。
- **闭环**：agentflow 数据源+generate+reward 插进 train_ray 跑通，reward_mean=1.0、weight_v→2（=num_rollout+1）。
- **回归**：V0(5/5)/V2(offline)/V3/V4/V5/A1(offline) 全绿——A2 只新增文件 + 加 Args 字段，对既有路径透明。

## 暴露的痛点（引出 A3）
