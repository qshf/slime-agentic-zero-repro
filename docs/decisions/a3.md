# A3 实施计划：ToolOrchestra QA 路径

> 状态：✅ 代码 + 离线闭环 + 5090 端到端全部完成（**主线二终点**）。
> 源锚点：`agentic/ToolOrchestra/{orchestra_solver.py,prompt_builder.py,reward.py,custom_convert.py}`。

## 目标

A3 是主线二终点：让可训练的 orchestrator 在多轮对话中选择 `search` 或 `answer`，并把答案任务路由给
不同专家。每轮只训练 orchestrator 的输出；工具结果以 `role="tool"` 写回下一轮 prompt，loss mask 为 0。

与 A2 的差别是状态：A2 的跨角色状态是 `Memory` 动作表；A3 QA 路径忠实采用源 ToolOrchestra 的
`messages -> assistant tool call -> tool result -> messages` 循环。这样执行失败会以结构化 tool event 回到
下一轮 orchestrator，而非仅由 verifier 推断。

## 范围

- 实现源 `OrchestraSolver._solve_qa` 的最小等价结构：orchestrator 多轮生成、`search`、`answer`、专家路由、
  tool messages、每轮独立 training turn。
- 实现两位逻辑专家（`expert_fast` / `expert_precise`），用任务 metadata 的价格和偏好权重计算成本/延迟/路由
  效用。
- 实现离线 deterministic stub 和现有 SGLang endpoint 的真实入口。
- 不实现源 `func_call` / Tau2 进程环境、FAISS 服务、外部多 SGLang 专家集群、源 `custom_convert` 的同题多
  rollout min-max/GRPO 标准化。

## 设计

1. `events` 是权威执行记录。每条含 `tool_name`、`role_name`、`status`、`input`、`output`、`error`、
   `input_tokens`、`output_tokens`、`latency_ms`。绝不以字符串猜测错误状态。
2. `messages` 是 orchestrator 的上下文视图。每次工具结果追加为 `role="tool"`；下一轮完整渲染，工具
   observation 永远不进入 training turn。
3. `answer` 专家失败时，结构化 error message 回到 orchestrator，允许它改选专家或改走 search；由
   `orchestra_max_steps` 兜底。
4. 当前 mini 框架的 reward hook 是 per-sample，不能复刻源 `custom_convert` 的同题多 rollout 比较。因此 A3
   采用确定性单样本 utility：错误答案为 0；正确答案按 metadata 的 `accuracy`、`cost`、`latency`、专家角色
   偏好加权，成本/延迟按每题预算归一化。该偏离不改变多组件 reward 的数据流，真 GRPO group normalization
   留主线三。

- `toy_rl/agent/toolorchestra/{data,prompt,solver,rollout,stub_rollout}.py`
- `mini_slime/args.py` 增加 A3 专属 endpoint/轮数/预算字段。

- `scripts/test_a3_toolorchestra.py` 是服务器入口；真实模型只断言轨迹与 reward 契约，不把离线的固定路由
  当作模型能力断言。

## 验收标准

1. offline 路径使用 `search -> answer(expert)` 两轮，tool message 会进入第二轮 prompt。
2. 每个 turn 的 `loss_mask` 仅覆盖 orchestrator response；tool result 只出现在后续 prompt 的 0-mask 区。
3. 选择低成本/低延迟且偏好更高的专家，在答案同样正确时有更高 reward。
4. A1/A2 及 V0/V2/V3/V4/V5 现有测试不受影响。

## 验证结果

- `scripts/test_a3_toolorchestra.py --offline`：通过。验证 `search -> answer(expert_fast)` 两轮 messages
  反馈、仅 orchestrator token 训练、成本/延迟/路由偏好的 utility，以及 expert 失败后由 tool error message
  触发 `expert_precise -> expert_fast` 重路由。
- A3 通过 `train_ray` 的 fake-trainer 闭环，离线 `reward_mean=0.991`。
- **全套 offline 回归绿**（服务器 a3 checkout）：V0 5/5、V2/V3/V4/V5/A1/A2 全 PASSED、A3 offline + 闭环
  通过。A3 改造对主线一/A1/A2 零影响。
- **5090 端到端 PASSED**（真 4B orchestrator @30001）：`server turns=2 events=2 reward=0.880`。真实轨迹——
  orchestrator 第一轮自主选 `search`（拿到证据）→ 第二轮 `answer` 路由到 `expert_fast` → 专家算出
  `\boxed{165}`。契约全绿（turns 全 orchestrator、`len(tokens)==len(loss_mask)`、
  `sum(loss_mask)==sum(response_length)`、reward∈[0,1]）。多组件 reward 生效：correctness=1.0、
  total_cost=0.000656、total_latency≈10.4s、tool_counts={expert_fast:1} → 加权 reward=0.880（非满分正是
  成本/延迟组件起作用，这是 A3 相对 A2 单 reward 的核心增量）。

## 偏离登记（按铁律三要素）

| 偏离点 | ①源怎么做 | ②为何偏离 | ③等价性/何时补齐 |
|---|---|---|---|
| **单样本预算归一 reward，无组内 GRPO min-max**（A3 最大语义偏离） | 源 `custom_convert.py:53-155` 把同题多 rollout 的 cost/latency 做**组内 min-max 相对归一** + 偏好加权 + GRPO 标准化 `(r-mean)/(std+eps)` clip[-3,3] + std<0.1 过滤 | mini 框架 reward hook 是 **per-sample**，拿不到同题多 rollout，无法做组内比较 | **语义不等价**——nano 改成"错误答案 0 / 正确答案按 metadata 的 accuracy/cost/latency/角色偏好加权、成本延迟按每题预算归一"（`rollout.py:94-113`）。多组件 reward 的**数据流保留**（features→加权），真组内 min-max/GRPO 标准化留主线三 |
| **prompt 手工渲染单段文本**（非 `apply_chat_template(tools=)`） | 源 `_generate_with_tools` 用 `tokenizer.apply_chat_template(messages, tools=..., add_generation_prompt=True)` | nano 无真 tokenizer；且手工渲染保 RL token/log_prob 边界清晰（同 A2 登记） | 主流程等价（messages+tool schema→单段 prompt→chat completion）；真 chat_template 留 V6 |
| **无 FAISS 检索服务**，search 从 metadata 注入 | 源 `SearchRetrievalTool` 调 `retrieval_url`(FAISS 8000) 真检索 | nano 不起检索服务；search 结果由数据 `metadata["search_context"]` 提供 | search 作为"非终止工具、结果回灌下一轮 prompt"的**结构语义等价**；真 FAISS 留主线三 |
| **只做 QA 路径，砍 func_call/tau2** | 源 `solve()` 按 category 分 `_solve_qa`/`_solve_func_call`（tau2 子进程环境模拟器） | 路线图既定——func_call+tau2 环境模拟器忠实复现基本不可能，记录设计不实现 | QA 路径忠实；func_call/tau2 不补齐（记录设计，见 system-roadmap） |
| **专家/搜索工具只两个逻辑角色** | 源工具 enhance_reasoning/search/answer + expert_caller(多专家 engine_map) | nano 只需 search + answer(expert_fast/expert_precise) 说清"多专家路由 + 成本/延迟权衡" | 路由分发语义等价（tool_name→执行、expert→角色查 model_mapping）；更多工具/专家可加 |
| **无 expert 熔断器** | 源 `_expert_consecutive_failures` + `circuit_breaker_limit=2` | nano max_steps 兜底 + 错误 event 回灌已足够说清"失败结构化回流触发重路由" | 主流程等价（失败→error event→orchestrator 重路由）；熔断是工程加固，不改语义 |
| **字符级假 token / 无真 log_probs** | /generate 真 tokenizer + log_probs | 沿用 V1-V5/A1/A2 | loss_mask 构造等价；真 tokenizer 留 V6 |
| **硬编码多步计算 QA** | 源数据集 JSONL 加载 | 只需跑通闭环 | 结构等价（prompt/label/metadata 形态一致） |
