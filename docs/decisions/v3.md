## Context（为什么做 V3）

V2 结束时的痛点（见 [v2.md](v2.md) 末尾）：
- 已有可插拔的 `generate` / `reward_func` hook，但**还是在测试脚本里手动一次次调**，没有编排 `rollout→train→update_weights` 的循环。
- rollout 和 train 逻辑挤在 `test_*.py` 里，**没有独立的 RolloutManager / Trainer 角色**。

V3 要做的：搭出 **mini_slime 的最小闭环骨架**——把"谁负责产数据、谁负责训、谁负责同步权重"这三个角色分开，用一个主循环串起来，输出各阶段指标。**这是主线一从"单次调用"迈向"训练系统"的关键一版。**

## 源项目骨架（已读实证，V3 要对齐的形状）

同步主循环 `train.py:65-93`（去掉 critic/offload/eval 噪声后的骨架）：
```python
for rollout_id in range(args.start_rollout_id, args.num_rollout):
    rollout_data_ref = ray.get(rollout_manager.generate.remote(rollout_id))  # 产数据
    ray.get(actor_model.async_train(rollout_id, rollout_data_ref))           # 训
    actor_model.update_weights()                                             # 同步权重回推理引擎
```
- `RolloutManager.generate(rollout_id)`（rollout.py:539）：`_get_rollout_data`（调 generate hook 跑 SGLang 产 Sample）→ `_convert_samples_to_train_data`（**Sample 列表 → dict**，rollout.py:737）→ `_split_train_data_by_dp`（按 DP 切分）。
- 流动的数据契约（`_convert_samples_to_train_data` 产物）：
  ```python
  {"tokens": [...], "loss_masks": [...], "rewards": [...],
   "response_lengths": [...], "rollout_log_probs": [...], ...}
  ```
- `actor.train(rollout_id, rollout_data)`（actor.py:437）：消费上面的 dict，跑 forward/backward。
- `actor.update_weights()`（actor.py:725）：把训练后权重 bucket-by-bucket 广播回 SGLang 推理引擎。

## V3 要建的文件（单进程、串行、无 Ray）

> V3 **不引入 Ray**（那是 V4）。角色用**普通类**，主循环**串行直调**（不用 `.remote()`/`ray.get`）。

### `mini_slime/rollout_manager.py` — RolloutManager
对齐源 `RolloutManager`，但去掉 Ray/DP：
```python
class RolloutManager:
    def __init__(self, args):
        self.args = args
        self.data_source = _load_prompts(args)                    # 对齐源 data_source（V3 用硬编码小题库）
        self.generate = load_function(args.custom_generate_function_path)   # V2 的 hooks.load_function
        self.reward_func = load_function(args.custom_rm_path)

    async def generate_rollout(self, rollout_id: int) -> dict:
        # 对齐源 generate: 取一批 prompt → 逐条跑 generate hook（真 SGLang）→ reward_func → 转 train_data dict
        samples = []
        for prompt, label in self._next_batch(rollout_id):
            s = Sample(prompt=prompt, label=label)
            s = await self.generate(self.args, s)                 # 真 SGLang rollout（复用 V1/V2 loop）
            s.reward = (await self.reward_func(self.args, s))["reward"]
            samples.append(s)
        return _convert_samples_to_train_data(samples)            # Sample 列表 → dict（见下）
```

### `mini_slime/rollout_manager.py` 内的 `_convert_samples_to_train_data(samples) -> dict`
对齐源 rollout.py:737——**这是 V3 最核心的教学点**：训练器不认识 Sample，只认字段对齐的 dict。
```python
def _convert_samples_to_train_data(samples):
    return {
        "tokens":           [s.tokens for s in samples],
        "loss_masks":       [s.loss_mask for s in samples],
        "rewards":          [s.reward for s in samples],
        "response_lengths": [len(s.tokens) for s in samples],   # V1 用全长；真 response_length 留 V6
        # rollout_log_probs 源项目有；V1/V2 打 chat 端点拿不到，留 V6（见偏离说明）
    }
```

### `mini_slime/trainer.py` — Trainer（fake）
对齐源 `actor` 的**角色与签名**，但**不算真梯度**：
```python
class Trainer:
    def __init__(self, args):
        self.weight_version = 0
    def train(self, rollout_id: int, rollout_data: dict) -> dict:
        # 对齐 actor.train 签名（消费 train_data dict）。V3 fake：不 forward/backward，
        # 只消费数据结构、产出可断言的指标（如 mean reward、trainable token 数）。
        rewards = rollout_data["rewards"]
        n_trainable = sum(sum(m) for m in rollout_data["loss_masks"])
        return {"reward_mean": sum(rewards)/len(rewards), "trainable_tokens": n_trainable}
    def update_weights(self) -> None:
        # 对齐 actor.update_weights 角色。V3 fake：不广播真张量，bump 版本号 + 记日志。
        self.weight_version += 1
```

### `mini_slime/train.py` — 主循环
对齐 `train.py:65-93` 骨架：
```python
async def main(args):
    rm = RolloutManager(args)
    trainer = Trainer(args)
    metrics_log = []
    for rollout_id in range(args.num_rollout):
        t0 = time.time(); rollout_data = await rm.generate_rollout(rollout_id); t_gen = time.time()-t0
        t0 = time.time(); m = trainer.train(rollout_id, rollout_data);          t_train = time.time()-t0
        t0 = time.time(); trainer.update_weights();                             t_sync = time.time()-t0
        metrics_log.append({"rollout_id": rollout_id, "gen_time": t_gen, "train_time": t_train,
                            "sync_time": t_sync, "reward_mean": m["reward_mean"],
                            "tokens_per_rollout": sum(rollout_data["response_lengths"])})
    return metrics_log
```

## 偏离说明（按铁律，三要素逐条写明）

| 偏离点 | ①源怎么做 | ②为何偏离 | ③等价性/何时补齐 |
|---|---|---|---|
| **无 Ray** | 源 RolloutManager/actor 是 `@ray.remote`，`.remote()`+`ray.get` 编排 | V3 目标是先看清**角色分离+串行闭环**，Ray 会淹没骨架 | 编排语义等价（同一调用序列）；Ray 化是 **V4** 承诺 |
| **fake trainer（不算真梯度）** | 源 `actor.train` 跑真 FSDP/Megatron forward/backward | 主线一聚焦**系统骨架/编排**，非训练数学；真 backend 是重依赖 | 角色/签名/数据契约等价，只是 train() 内部打桩；真训练器 backend 留**主线三 V6-V9** |
| **fake update_weights** | 源 bucket-by-bucket 广播真张量到 SGLang 引擎 | 无真训练器就无真权重可推；且需真 RolloutManager 引擎句柄 | 打点语义（"发生了一次权重同步"）等价；真权重同步留 **V6+** |
| **无 DP 切分** | 源 `_split_train_data_by_dp` 按 dp_size 切成多份 Box | V3 单进程 dp_size=1 | 等价（一份）；多 DP 留 V4 Ray 化 |
| **硬编码小题库 data_source** | 源 `data_source_cls(args)` 从数据集加载 prompt | V3 只需几条 calculator 题跑通闭环 | 角色等价；真数据加载留后续需要时 |
| **response_lengths=全长 / 无 rollout_log_probs** | 源从 SGLang `/generate` 拿真 token_ids + log_probs | V1/V2 打 chat 端点，拿不到真 log_probs（已在 v1 记录） | 结构占位等价；真 `/generate`+log_probs 留 **V6** |

**次级借鉴 nano_hermes**：本版无需借（编排骨架源项目已足够清晰）。

## 指标输出（V3 要采集的）
每轮：`gen_time` / `train_time` / `sync_time`（各阶段耗时）、`reward_mean`、`tokens_per_rollout`。
这些指标是 **V4/V5 的对照基线**——V4 Ray 化后看 train 是否与 gen overlap，V5 异步看总耗时是否下降。

## 验证
- `scripts/test_v3_loop.py`：跑 **2 轮**闭环（真 SGLang rollout + fake train/sync），断言：
  1. 每轮 metrics 字段齐全（gen/train/sync_time、reward_mean、tokens_per_rollout 都存在且类型对）。
  2. `trainer.weight_version == num_rollout`（每轮同步一次，权重版本正确递增）。
  3. rollout_data 契约：`len(tokens)==len(loss_masks)==len(rewards)==batch_size`，每条 `len(tokens[i])==len(loss_masks[i])`。
  4. reward_mean ∈ [0,1]。
- 本地离线：generate hook 可打桩（monkeypatch `_chat`）跑闭环，不连 SGLang。
- 服务器端到端：5090 真 SGLang 跑 `uv run python scripts/test_v3_loop.py`。

## 暴露的痛点（引出 V4）
- 主循环**全串行**：`generate` 跑 SGLang 时 trainer 空转，`train` 时推理引擎空转——GPU 利用率低。
- 单进程无法让 RolloutManager 和 Trainer 真正并行。
- → **V4 Ray 化**：RolloutManager/Trainer 改 `@ray.remote`，`ray.get` 做同步点，为 V5 的 generate(N+1)/train(N) overlap 铺路。

## 范围外（V3 不做）
- 不引入 Ray（V4）、不做异步 overlap（V5）。
- 不实现真训练器 backend / 真权重同步 / 真 log_probs（主线三 V6-V9）。
- 不碰 V1/V2 已定稿的 agent loop / Sample / hook 签名 / 工具层。
